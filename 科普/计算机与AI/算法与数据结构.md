# 算法与数据结构

> 子类：计算机与AI ｜ 难度：成人通识 ｜ 阅读时长：约 30 分钟

## 导语

同一个功能，为什么有的程序一眨眼就出结果，有的要转圈半分钟？为什么地图 App 能在几百万个路口里瞬间算出最短路线？为什么"从一亿个数字里找最大的那个"只要走一遍，而"给一亿个数字排序"就慢得多？

答案藏在两个词里：**数据结构**决定数据怎么摆，**算法**决定数据怎么处理。摆得好，事情就简单；摆得乱，再聪明的办法也费劲。

本篇不讲某门语言的实现细节，而是搭一张认知地图：先说清"怎么衡量快慢"（时间复杂度与大 O）；再逐一认识最常用的数据结构——数组、链表、栈、队列、哈希表、树、图；然后是排序与查找这两件最日常的事；接着进入三种思想工具——**分治、动态规划、贪心**；最后触到理论边界：P 与 NP。每章都配生活类比，因为好的直觉比背公式管用得多。

关键结论与出处均标注来源（如 `CLRS`、`Dijkstra, 1959`、`Cook, 1971`、`Karp, 1972`）。

## 第一章 算法是什么

### 1.1 算法与程序的区别

**算法（Algorithm）** 是"解决某类问题的有限步骤描述"；**程序（Program）** 是算法在某种语言中的具体实现。

| 对比 | 算法 | 程序 |
|------|------|------|
| 形态 | 抽象步骤、伪代码 | 可执行代码 |
| 关心 | 正确性与效率 | 还能跑起来、可维护 |
| 例子 | "二分查找的思路" | 某语言写的二分查找函数 |

经典教材 **CLRS**（Cormen, Leiserson, Rivest, Stein 合著《Introduction to Algorithms》）把算法定义为"**把输入转换为输出的一系列计算步骤**"。

> 来源：Cormen, T. H., Leiserson, C. E., Rivest, R. L., Stein, C., *Introduction to Algorithms*（首版 1990，第 4 版 2022，MIT Press）。书中算法均以伪代码描述，不绑定具体语言。

### 1.2 算法的五个特征

| 特征 | 含义 |
|------|------|
| 输入 | 有零个或多个输入 |
| 输出 | 至少产生一个输出 |
| 有穷性 | 有限步骤后终止（不能无限跑下去） |
| 确定性 | 每一步含义明确，无歧义 |
| 可行性 | 每一步都可由基本操作完成 |

**"有穷性"最容易被忽略**：一个不终止的过程不是算法，哪怕它方向正确。

### 1.3 "程序 = 数据结构 + 算法"

这句名言出自 Pascal 语言设计者、1984 年图灵奖得主 Niklaus Wirth 1976 年的同名著作。它想表达的是：

- 数据怎么组织（数据结构）与怎么处理（算法）是**一体两面**；
- 换一种数据结构，同一个问题可能从"很难"变成"很简单"。

一个经典例子：**判断一个列表中是否存在重复元素**。

| 数据结构选择 | 做法 | 时间复杂度 |
|--------------|------|------------|
| 用列表 | 两两比较 | O(n²) |
| 用哈希表 | 逐个插入并查是否已存在 | O(n) |

算法没变（都属于"逐个检查"），仅仅是换了个"放数据的容器"，复杂度就从平方降到线性。**这就是数据结构的威力。**

### 1.4 为什么值得学

| 收益 | 说明 |
|------|------|
| 写出更快的程序 | 复杂度差异在数据量大时是数量级的 |
| 更会分解问题 | 分治、动态规划是通用的思维工具 |
| 更容易读懂代码 | 一眼看出用的是哪种结构 |
| 面试与职业基础 | 大厂面试的通用语言 |

### 1.5 本篇的组织方式

```
怎么衡量好坏（第 2 章）
        ▼

        ▼

```

## 第二章 时间复杂度：怎么衡量"快"

### 2.1 为什么不用"秒"

同一段代码，在手机上跑 3 秒、在服务器上跑 0.1 秒。"3 秒"不说明算法好坏，只说明机器快慢。

因此需要一把**与机器无关**的尺子：数一数"基本操作的执行次数如何随输入规模 n 增长"。这就是**时间复杂度**。

### 2.2 大 O 记号

**大 O 记号（Big-O notation）** 描述增长率的上界，即"最坏情况下，工作量随 n 增长的量级"。

| 记号 | 名称 | n = 1000 时的量级感受 | 典型算法 |
|------|------|------------------------|----------|
| O(1) | 常数 | 1 | 数组按下标取值、哈希表查找（均摊） |
| O(log n) | 对数 | 约 10 | 二分查找、平衡树查找 |
| O(n) | 线性 | 1000 | 顺序查找、遍历数组 |
| O(n log n) | 线性对数 | 约 10000 | 归并排序、堆排序 |
| O(n²) | 平方 | 100 万 | 冒泡排序、双重循环 |
| O(2ⁿ) | 指数 | 天文数字 | 穷举子集的暴力解法 |
| O(n!) | 阶乘 | 不可行 | 穷举所有排列 |

**直观图**（横轴为 n，纵轴为工作量）：

```
工作量
  │                                    ╱ O(2ⁿ)
  │                                 ╱
  │                              ╱
  │                          ╱ O(n²)
  │                    ╱
  │            ╱──── O(n log n)
  │      ╱──── O(n)
  │  ╱─── O(log n)
  │────── O(1)
  └────────────────────────────────▶ n
```

**关键直觉**：小数据量时差距不明显，n 一大就天差地别。n = 100 万时，O(n log n) 与 O(n²) 的差距约在十万倍量级——这正是一个"秒回"和一个"卡死"的区别。

### 2.3 关于大 O 的三个常见误解

| 误解 | 澄清 |
|------|------|
| 大 O 就是"运行时间" | 它描述**增长趋势**，不是绝对值；小 n 时常数项更重要 |
| 必须写出精确的 O | 一般只保留最高次项、忽略常数：O(3n² + 5n + 7) 记作 O(n²) |
| O 就是"最坏情况" | 严格说 O 是上界；Θ 是紧确界；Ω 是下界。日常口语常混用 |

**为什么可以忽略常数？** 因为当 n 足够大时，n² 的增长会彻底压过常数。但工程实践中，若 n 始终很小，"常数更小的 O(n²)"可能真的比"常数更大的 O(n)"更快——**这是理论与实践的常见分歧点**。

> 来源：大 O 记号源于数学家 Paul Bachmann 与 Edmund Landau 的渐近分析工作，后由计算机科学家 Donald Knuth 引入算法分析并推广（Knuth 于 1974 年获图灵奖）。

### 2.4 空间复杂度

**空间复杂度**衡量算法额外占用的内存随 n 的增长。

| 例子 | 时间 | 额外空间 |
|------|------|----------|
| 就地冒泡排序 | O(n²) | O(1) |
| 归并排序 | O(n log n) | O(n) |
| 用哈希表去重 | O(n) | O(n) |

**"时间换空间"与"空间换时间"是最经典的工程权衡**。缓存（见《计算机原理与组成》）正是"用空间换时间"的规模化应用。

### 2.5 怎么估算一段代码的复杂度

一套可操作的流程：

1. **找出输入规模 n** 是什么（数组长度？节点数？位数？）；
2. **看循环**：单层循环通常是 O(n)，嵌套两层通常是 O(n²)；
3. **看是否每次减半**：每次把问题规模变成原来的一半 → O(log n)；
4. **看是否分而治之**：拆成 a 个子问题、每个规模 n/b → 通常形如 O(n log n)；
5. **取最大项、去常数**。

多段代码**顺序执行取最大**，两层循环**相乘**：

```
for i in 1..n:        ← O(n)
    for j in 1..n:    ← 相乘 → O(n²)
        ...

for k in 1..n:        ← O(n)，与上面的 O(n²) 相比可忽略
    ...
```

### 2.6 均摊复杂度

有些操作偶尔很慢，但长期平均很快，这叫**均摊（amortized）**分析。

典型例子：**动态数组的扩容**。数组满了才翻倍扩容一次，那一次需要复制全部元素（O(n)），但平摊到每次追加操作上仍是 O(1)。

> 注意"均摊"（amortized）与"平均"（average）不同：均摊是对**最坏情况序列**取平均，不依赖输入的概率假设。

## 第三章 基础数据结构：数组与链表

### 3.1 数组（Array）

**数组**是最基础的容器：**一段连续的内存，元素按下标随机访问**。

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 按下标读取/写入 | O(1) | 直接算出地址 |
| 末尾追加 | O(1) 均摊 | 需扩容时复制 |
| 中间插入/删除 | O(n) | 后面元素要整体搬家 |
| 查找某值 | O(n) | 只能从头扫 |

**为什么下标访问是 O(1)？** 因为地址 = 起始地址 + 下标 × 元素大小，一步算出来。这是数组最大的优势。

**生活类比**：数组像**电影院的连号座位**。你凭座位号可以一步走到自己的位置（随机访问），但如果要在第 3 排和第 4 排之间"再插一排人"，后面所有人都得往后挪（插入 O(n)）。

### 3.2 链表（Linked List）

**链表**由一个个节点组成，每个节点存"数据 + 指向下一个节点的指针"，节点之间在内存里不必相邻。

| 操作 | 复杂度（已知位置） | 说明 |
|------|--------------------|------|
| 头部插入/删除 | O(1) | 改几个指针 |
| 中间插入/删除 | O(1) | 前提是已拿到那个节点 |
| 按下标访问 | O(n) | 必须从头一个个走 |
| 查找某值 | O(n) | 无法跳着找 |

**生活类比**：链表像**藏宝游戏**。每张线索纸条上都写着"下一张纸条藏在哪"。想找第 10 张线索，你必须按顺序找过去（访问 O(n)）；但如果你想在某张线索后"再插一条新线索"，只需改一下纸条内容（插入 O(1)）。

### 3.3 数组 vs 链表

| 对比 | 数组 | 链表 |
|------|------|------|
| 内存布局 | 连续 | 分散 + 指针 |
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n) | O(1) |
| 缓存友好度 | 好（连续访问快） | 差（跳来跳去） |
| 额外空间 | 无 | 每个节点要存指针 |
| 扩容 | 可能需整体复制 | 天然可增长 |

**一个容易被忽略的因素：CPU 缓存**。即使理论复杂度相同，数组往往远快于链表，因为连续内存能充分利用缓存行（见《计算机原理与组成》）。**理论复杂度相同 ≠ 实际速度相同**。

### 3.4 数组的变体

| 变体 | 特点 | 适用 |
|------|------|------|
| 动态数组 | 自动扩容（通常按倍数增长） | 通用列表 |
| 多维数组 | 矩阵、图像 | 科学计算、图形 |
| 环形缓冲区 | 首尾相接的定长队列 | 音视频流、日志缓冲 |
| 稀疏矩阵 | 只存非零元素 | 大规模稀疏数据 |

### 3.5 链表家族

| 类型 | 特点 | 用途 |
|------|------|------|
| 单链表 | 只有 next 指针 | 最简实现 |
| 双向链表 | 有 prev 和 next | 需反向遍历、O(1) 删除已知节点 |
| 循环链表 | 尾节点指回头节点 | 轮询调度、约瑟夫环 |

**"用数组还是链表"是工程中最常见的选型问题之一**，判断依据通常只有两条：是"频繁随机访问"还是"频繁中间增删"。

## 第四章 栈与队列：两种受限但极有用的结构

栈和队列都是"操作受限的容器"。**限制不是缺陷，而是把结构变得可预测**，从而带来简洁的语义。

### 4.1 栈（Stack）：后进先出

**栈**只允许在一端（栈顶）插入和删除，遵循 **LIFO（Last In, First Out，后进先出）**。

| 操作 | 复杂度 |
|------|--------|
| 压栈 push（入） | O(1) |
| 弹栈 pop（出） | O(1) |
| 查看栈顶 peek | O(1) |

**生活类比**：**叠盘子**或**弹匣压子弹**。你只能从最上面拿，最后放进去的最先被取出。

栈的典型应用：

| 场景 | 为什么用栈 |
|------|------------|
| 函数调用 | 每层调用压入一个"栈帧"，返回时弹出——这就是"调用栈" |
| 撤销操作（Ctrl+Z） | 每次操作压栈，撤销时弹出 |
| 括号匹配 | 遇左括号压栈，遇右括号弹栈比对 |
| 表达式求值 | 中缀转后缀、后缀求值 |
| 深度优先搜索（DFS） | 用栈模拟递归 |
| 浏览器的后退 | 访问记录压栈 |

**"函数调用栈溢出"** 就是这么来的：递归太深，栈帧不断堆积，超出栈空间限制。

### 4.2 队列（Queue）：先进先出

**队列**一端进、另一端出，遵循 **FIFO（First In, First Out，先进先出）**。

| 操作 | 复杂度 |
|------|--------|
| 入队 enqueue | O(1) |
| 出队 dequeue | O(1) |

**生活类比**：**排队买票**。先来的人先办完，后来的人排到队尾。

队列的典型应用：

| 场景 | 为什么用队列 |
|------|--------------|
| 任务调度 | 先到先服务（打印队列） |
| 广度优先搜索（BFS） | 逐层扩展 |
| 消息队列 | 削峰填谷、服务解耦 |
| 缓冲区 | 生产者-消费者模型 |
| 请求排队 | 限流与公平调度 |

### 4.3 变体：优先队列与双端队列

| 结构 | 规则 | 典型实现 | 用途 |
|------|------|----------|------|
| 优先队列 | 按优先级出队，而非按到达顺序 | 二叉堆 | 任务调度、Dijkstra 算法 |
| 双端队列（Deque） | 两端都能进能出 | 双向链表/环形数组 | 滑动窗口最值 |
| 单调队列 | 队列内元素保持单调 | 双端队列 | 滑动窗口最大值 O(n) |

**优先队列的直觉**：医院急诊不是"先来先看"，而是"病重先看"——这就是优先队列。

### 4.4 一个经典对照：BFS 与 DFS

| 对比 | BFS（广度优先） | DFS（深度优先） |
|------|-----------------|-----------------|
| 数据结构 | 队列 | 栈（或递归） |
| 扩展方式 | 一层一层向外 | 一条路走到底再回头 |
| 是否最短路径 | 无权图下是 | 不一定 |
| 内存占用 | 通常更耗（存一层） | 通常更省 |
| 适合 | 最短路径、层级遍历 | 拓扑排序、连通性、回溯 |

**生活类比**：BFS 像**往水里扔石子形成的涟漪**，一圈一圈扩散；DFS 像**走迷宫时死磕一条通道**，走到死胡同再退回上一个岔路口。

## 第五章 哈希表：用空间换时间的典范

### 5.1 核心思想

**哈希表（Hash Table）** 用一个**哈希函数**把"键"映射到数组的某个位置，从而实现平均 O(1) 的查找、插入、删除。

```
键 "apple" ──哈希函数──▶ 3 ──▶ 数组[3] 处存放对应值
```

**生活类比**：**图书馆按书名字母分区上架**。你不需要从第一本翻到最后一本（O(n)），而是直接走到 A 区找《算法导论》——一步定位。

### 5.2 复杂度

| 操作 | 平均 | 最坏 |
|------|------|------|
| 查找 | O(1) | O(n) |
| 插入 | O(1) | O(n) |
| 删除 | O(1) | O(n) |

最坏情况（所有键都撞到同一个位置）会退化成链表，故为 O(n)。

> 来源：Cormen 等，*Introduction to Algorithms* 第 4 版第 11 章"Hash Tables"。第 4 版新增了该章的若干修订内容。

### 5.3 哈希冲突：无法回避，只能处理

不同键映射到同一位置叫**冲突（collision）**。因为定义域（可能的键）通常远大于值域（数组长度），冲突是**数学上必然**的。

| 解决策略 | 做法 | 特点 |
|----------|------|------|
| 链地址法 | 同一位置的元素串成链表/树 | 实现简单，负载高时性能降 |
| 开放寻址法 | 冲突时按规则找下一个空位 | 缓存友好，删除处理复杂 |

**负载因子（load factor）= 元素数 / 桶数**。超过阈值（常用 0.75 上下）就扩容并重新哈希，以维持性能。

### 5.4 好哈希函数的四条要求

1. **计算快**；
2. **分布均匀**（减少冲突）；
3. **确定性**（同键必得同值）；
4. **抗碰撞**——注意：**这里只要求"尽量减少冲突"，与密码学哈希要求的"抗恶意构造"不是一回事**。

> 重要区分：数据结构里的哈希表追求**快**；密码存储用的密码学哈希（如 Argon2）**故意设计得很慢**。同名不同命，切勿混淆（详见《数据安全与隐私保护》第四章）。

### 5.5 哈希表的现实应用

| 场景 | 作用 |
|------|------|
| 字典 / 映射 | 键值对存储 |
| 去重 | 判断是否已出现过 |
| 缓存（Cache） | 以请求为键快速命中 |
| 数据库索引 | 等值查询加速 |
| 路由表 | 按前缀/键分发 |
| 布隆过滤器 | 用极省空间判断"可能存在/一定不存在" |

### 5.6 布隆过滤器：一个精妙的小结构

**布隆过滤器（Bloom Filter）** 用一个位数组和多个哈希函数，回答"这个元素在不在集合里"：

- 说"**不在**"→ **一定不在**（无假阴性）；
- 说"**在**"→ **可能不在**（有假阳性）。

它只占极小空间，代价是"允许误判"。用于"防止重复爬取""拦截垃圾邮件黑名单预判"等场景——先快速过滤掉绝大多数，再对少数做精确查询。

## 第六章 树：有层次的数据

### 6.1 为什么需要树

数组与链表都是"一条线"，而现实中的数据常常是**有层次的**：文件目录、组织架构、网页链接、语法结构。**树（Tree）** 正是描述层次关系的结构。

一棵树由**节点**与**边**组成，有唯一的**根**，没有环。

| 概念 | 含义 |
|------|------|
| 根 | 最顶层节点 |
| 父/子节点 | 上下相邻的节点 |
| 叶子 | 没有子节点的节点 |
| 高度/深度 | 层数 |
| 子树 | 某个节点及其后代构成的树 |

### 6.2 二叉树与遍历

**二叉树**每个节点最多两个子节点（左、右）。遍历方式有三种：

| 遍历 | 顺序 | 用途 |
|------|------|------|
| 前序 | 根 → 左 → 右 | 复制树、序列化 |
| 中序 | 左 → 根 → 右 | **二叉搜索树可得有序序列** |
| 后序 | 左 → 右 → 根 | 释放内存、计算子树结果 |
| 层序 | 逐层，用队列 | 按层处理 |

**生活类比**：遍历一棵公司组织树——前序是先说 CEO 再说各部门（自顶向下交代）；后序是先汇报各部门业绩再汇总到 CEO（自底向上汇总）。

### 6.3 二叉搜索树（BST）

**二叉搜索树**的规则：任一节点，**左子树所有值 < 该节点 < 右子树所有值**。

| 操作 | 平均（平衡时） | 最坏（退化成链） |
|------|----------------|------------------|
| 查找 | O(log n) | O(n) |
| 插入 | O(log n) | O(n) |
| 删除 | O(log n) | O(n) |

**退化问题**：如果按 1、2、3、4……的顺序依次插入，BST 会变成一条链表，所有操作退化为 O(n)。**这正是"平衡树"存在的理由。**

### 6.4 平衡树家族

| 结构 | 平衡方式 | 特点 |
|------|----------|------|
| AVL 树 | 严格保持左右高度差 ≤ 1 | 查找快，插入删除旋转多 |
| 红黑树 | 近似平衡，用颜色约束 | 插入删除旋转少，工程中更常见 |
| B 树 / B+ 树 | 多路、矮胖 | **数据库与文件系统的索引结构** |
| 堆（Heap） | 只保证父子大小关系 | 优先队列、堆排序 |
| Trie（前缀树） | 按字符逐层分叉 | 自动补全、敏感词过滤 |

**为什么数据库索引用 B+ 树而不是二叉树？** 因为磁盘 I/O 按"块"进行。B+ 树每个节点能放几百个键，树高只有三四层，**一次查询只需很少几次磁盘读取**——这是"降低树高以匹配磁盘块大小"的经典设计。

### 6.5 堆：只关心"谁最大/最小"

**堆**是一棵完全二叉树，满足"父节点不小于（或不大于）子节点"：

| 类型 | 性质 | 应用 |
|------|------|------|
| 大顶堆 | 根是最大值 | 优先队列、求 top-k |
| 小顶堆 | 根是最小值 | 优先队列、合并有序流 |

堆的关键操作：

| 操作 | 复杂度 |
|------|--------|
| 取最值 | O(1) |
| 插入 | O(log n) |
| 取出最值 | O(log n) |
| 建堆 | O(n) |

**生活类比**：**公司里的职级汇报线**——你不需要知道所有人排序，但"最高负责人"永远在最上面，随时可问。

### 6.6 Trie 前缀树

**Trie** 把字符串按字符逐层展开，公共前缀共享节点。

```
        root
       ╱    ╲
      c      d
      │      │
      a      o
     ╱ ╲     │
    r   t    g
   ╱    │
  ╱     │
 car   cat  dog
```

| 优点 | 缺点 |
|------|------|
| 前缀查询极快 | 空间占用大 |
| 支持自动补全、前缀统计 | 实现比哈希表复杂 |

**典型应用**：输入法联想、搜索框自动补全、IP 路由表（前缀匹配）、敏感词过滤。

## 第七章 图：描述"关系"的终极结构

### 7.1 图的定义与分类

**图（Graph）** 由**顶点（Vertex）** 和**边（Edge）** 组成，用来描述"谁和谁有关系"。

| 分类维度 | 类型 | 例子 |
|----------|------|------|
| 边有无方向 | 有向图 / 无向图 | 微博关注（有向）/ 微信好友（无向） |
| 边有无权重 | 带权 / 无权 | 地图距离（带权）/ 是否认识（无权） |
| 是否有环 | 有环 / 无环（DAG） | 任务依赖通常是 DAG |
| 边是否稠密 | 稠密图 / 稀疏图 | 决定存储方式选择 |

**现实中的图无处不在**：社交网络、地图路网、网页链接、依赖关系、化学分子、电力网络。

### 7.2 两种存储方式

| 方式 | 结构 | 空间 | 适合 |
|------|------|------|------|
| 邻接矩阵 | n×n 二维数组，`matrix[i][j]` 表示 i→j 有无边 | O(n²) | 稠密图、需快速判断两点是否相邻 |
| 邻接表 | 每个顶点挂一个链表/数组，存它的邻居 | O(n + m) | 稀疏图（现实绝大多数） |

> 约定：n 为顶点数，m 为边数。

**选择直觉**：社交网络有几亿用户但每人只关注几百人 → 邻接表；小规模且需要频繁"两点是否相连"判断 → 邻接矩阵。

### 7.3 图的两个基本遍历

| 遍历 | 用的结构 | 特点 |
|------|----------|------|
| BFS | 队列 | 按"距离层数"扩展，无权图可求最短路径 |
| DFS | 栈/递归 | 一条路走到底，适合连通性、拓扑、回溯 |

两者复杂度均为 O(n + m)（邻接表）。

**经典应用**：

- **连通分量**：一个社交网络里有几个互不相通的圈子；
- **环检测**：判断任务依赖里有没有死循环；
- **二分图判定**：能否把人群分成两组、组内互不冲突。

### 7.4 最短路径

**最短路径**是最经典的图问题：从起点到终点，路最短（或代价最小）。

| 算法 | 适用 | 复杂度（常见实现） | 思想 |
|------|------|--------------------|------|
| BFS | 无权图 | O(n + m) | 逐层扩展，第一次到达即最短 |
| Dijkstra | 非负权图 | O((n+m) log n) | 贪心 + 优先队列 |
| Bellman-Ford | 可有负权边 | O(n·m) | 反复松弛，可检测负权环 |
| Floyd-Warshall | 所有点对 | O(n³) | 动态规划 |

**Dijkstra 算法**由荷兰计算机科学家 Edsger W. Dijkstra 于 1956 年构思、1959 年发表，题为 *A note on two problems in connexion with graphs*（发表于 *Numerische Mathematik*）。

**它的直觉**：像水面从起点开始扩散，每次从"当前已知最短的未确定点"出发，更新它的邻居。前提是**边权非负**——有负权边时贪心会失效。

> Dijkstra 于 1972 年获图灵奖。地图导航的路径规划，其核心正是这类最短路径算法（工程上会配合启发式搜索、分层路网等优化）。

### 7.5 最小生成树

**最小生成树（MST）**：用最小的总代价把图中所有顶点连通起来（不加多余边）。

| 算法 | 思想 | 复杂度 |
|------|------|--------|
| Kruskal | 按边权从小到大加边，用并查集防环 | O(m log m) |
| Prim | 从一个点出发，每次加入最近的邻居 | 取决于数据结构 |

**生活类比**：**给若干村庄铺路，要求总造价最低且村村可达**——正是最小生成树。

### 7.6 拓扑排序

**拓扑排序**给有向无环图（DAG）的顶点排出一个线性顺序，使得每条边都"从前指向后"。

**生活类比**：**课程先修关系**。要列出"先学 A 才能学 B"的合理修课顺序。

| 要点 | 说明 |
|------|------|
| 有环则无拓扑序 | 环意味着"互相依赖"，任务永远无法开始 |
| 实现 | Kahn 算法（BFS + 入度）或 DFS 逆后序 |
| 应用 | 构建系统、任务调度、依赖解析、电子表格重算 |

## 第八章 排序：最日常的算法

### 8.1 为什么排序这么重要

排序看起来只是"把数字排好"，但它往往是更大任务的前置步骤：

- **二分查找**的前提是有序；
- **去重**可以扫描有序序列后比较相邻项；
- **合并**多个数据源时，有序使归并变得简单；
- **数据库的 ORDER BY、GROUP BY** 都依赖排序。

### 8.2 主要排序算法对比

| 算法 | 平均时间 | 最坏时间 | 空间 | 稳定 | 特点 |
|------|----------|----------|------|------|------|
| 冒泡排序 | O(n²) | O(n²) | O(1) | 稳定 | 教学用，实际很少用 |
| 插入排序 | O(n²) | O(n²) | O(1) | 稳定 | **小数据或近乎有序时很快** |
| 选择排序 | O(n²) | O(n²) | O(1) | 不稳定 | 交换次数少 |
| 希尔排序 | 取决于增量 | — | O(1) | 不稳定 | 插入排序的改进 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 稳定 | 稳定、可外部排序 |
| 快速排序 | O(n log n) | O(n²) | O(log n) | 不稳定 | **实际最快**，需随机化 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 不稳定 | 最坏也稳定，缓存不友好 |
| 计数排序 | O(n + k) | O(n + k) | O(k) | 稳定 | **非比较排序**，值域小时极快 |
| 基数排序 | O(d·(n + k)) | 同左 | O(n + k) | 稳定 | 按位排序，适合定长数据 |
| 桶排序 | O(n + k) 平均 | O(n²) | O(n + k) | 稳定 | 数据分布均匀时极快 |

> 来源：算法性质与复杂度为 CLRS 等经典教材的标准结论。"稳定"指相等元素的相对次序在排序后保持不变。

### 8.3 稳定排序为什么重要

**稳定性（stability）**：值相等的元素，排序前后相对顺序不变。

**生活类比**：**先按成绩排名，再按班级排名**。如果第二趟排序稳定，那么同班同学之间仍保持按成绩的高低顺序。

如果第二趟不稳定，同班内成绩的先后就被打乱了——这在实际业务里会导致"结果不可复现"的 bug。

### 8.4 快排为什么快，又为什么不稳

**快速排序**的思想是**分治**：选一个基准（pivot），把数组分成"小于基准"和"大于基准"两半，再各自递归。

| 优点 | 风险 |
|------|------|
| 常数小、缓存友好，实测最快 | 若每次选的基准都是最值，退化为 O(n²) |
| 原地排序，空间省 | 不稳定的排序 |

**工程上的对策**：

1. **随机选基准**，让最坏情况几乎不可能被构造；
2. **三数取中**（取首、中、尾的中位数）；
3. **小区间切换插入排序**（小数组上插入排序常数更小）；
4. **三路划分**处理大量重复元素。

> 提示：许多标准库的排序并非"纯快排"，而是**混合排序**（如 introsort：快排 + 堆排序 + 插入排序的组合），以同时获得平均快与最坏可控。具体实现以各语言标准库文档为准。

### 8.5 比较排序的下界

一个深刻结论：**任何基于两两比较的排序，最坏情况下至少需要 Ω(n log n) 次比较**。

直觉理解：n 个元素共有 n! 种排列，每次比较最多把可能性分成两半，所以至少需要 log₂(n!) ≈ n log n 次比较才能区分所有情况。

**这也解释了为什么计数排序、基数排序能"突破" n log n**——它们**不靠比较**，而是利用数值本身的特性（值域有限、可分解为位）。**打破下界的方式是不在比较模型的框架内玩。**

## 第九章 查找：从一堆数据里找到那个

### 9.1 三种基本查找

| 方法 | 前提 | 时间 | 说明 |
|------|------|------|------|
| 顺序查找 | 无 | O(n) | 最简单，小数据够用 |
| 二分查找 | **必须有序** | O(log n) | 每次砍一半 |
| 哈希查找 | 可哈希 | O(1) 平均 | 用空间换时间 |
| 树查找 | 建了索引 | O(log n) | 支持范围查询 |

### 9.2 二分查找：为什么 log n 如此神奇

**二分查找**每一步把搜索范围减半：

| 数据量 n | 最多比较次数（约 log₂n） |
|----------|--------------------------|
| 10 | 4 |
| 100 | 7 |
| 1 万 | 14 |
| 100 万 | 20 |
| 10 亿 | 30 |

**10 亿条数据，最多 30 次比较就能定位。** 这是对数增长的威力。

**生活类比**：**猜数字游戏**。对方想一个 1—1000 的数，你每次猜中间值，对方告诉你"大了/小了"。你最多猜 10 次就能锁定——如果从 1 开始一个个猜，最坏要 1000 次。

### 9.3 二分查找的三个易错点

1. **数据必须有序**——无序数据先排序（排序 + 二分 vs 直接哈希，需按查询次数权衡）；
2. **边界与中点计算**：`mid = (low + high) / 2` 在极大数据下会整数溢出，宜写成 `low + (high - low) / 2`；
3. **终止条件与区间开闭**：`while (low <= high)` 还是 `while (low < high)`，取决于区间定义，混淆就会死循环或漏查。

**二分查找的"坑"是出了名的**——它思想极简单，但正确地写对边界并不容易。

### 9.4 更一般的"二分答案"

二分不只用于"在有序数组里找值"，还用于"**在一个单调的答案空间里找边界**"。

**生活类比**：**测体重秤的承重上限**。你不必逐一试 1kg、2kg……而是先试 100kg：没坏说明上限更高，坏了说明更低。反复折半，很快逼近真实上限。

**典型问题**：求最小的可行容量、最大的可行速度、第一个满足条件的值、最后一个不满足条件的值。

## 第十章 递归与分治：把大问题变成同类的小问题

### 10.1 递归的三个要素

**递归（Recursion）** 指函数调用自身来解决问题。

| 要素 | 说明 | 缺失后果 |
|------|------|----------|
| 基准情形（base case） | 最小规模、可直接回答 | 无限递归 → 栈溢出 |
| 递推关系 | 大问题如何化为小问题 | 无法推进 |
| 规模递减 | 每次调用必须更接近基准 | 无限递归 |

**生活类比**：**俄罗斯套娃**。你打开一层，里面是"同样但更小"的一个；一直开到最小那个（基准情形），再逐层合上返回结果。

### 10.2 递归 vs 迭代

| 对比 | 递归 | 迭代 |
|------|------|------|
| 可读性 | 对递归结构的问题更清晰 | 对线性流程更清晰 |
| 开销 | 每次调用有栈帧开销 | 通常更省 |
| 风险 | 深递归会栈溢出 | 无明显风险 |
| 转换 | 任何递归都可用栈改写为迭代 | 任何迭代也可改写为递归 |

**关键理解**：递归不是"更高级"，而是**更贴合某些问题的自然结构**（树、分治、回溯）。工程中若深度不可控，需改用迭代或"尾递归优化"（部分语言支持，如函数式语言；Python 与 Java 默认不支持）。

### 10.3 分治：分而治之

**分治（Divide and Conquer）** 三步：

```
① 分解（Divide）：把问题拆成若干个同类子问题
② 解决（Conquer）：递归求解子问题；足够小则直接解
③ 合并（Combine）：把子问题的解合成原问题的解
```

| 算法 | 分解方式 | 复杂度 |
|------|----------|--------|
| 归并排序 | 平均切两半 | O(n log n) |
| 快速排序 | 按基准划分 | 平均 O(n log n) |
| 二分查找 | 砍掉一半 | O(log n) |
| 大整数乘法（Karatsuba） | 拆成高位低位 | 优于朴素 O(n²) |
| 快速傅里叶变换（FFT） | 按奇偶下标拆分 | O(n log n)，多项式乘法核心 |

**生活类比**：**数一箱硬币有多少枚**。一个人数要数半天；做法是分成四堆让四个人各数一堆，最后把四人的结果加起来。分治的收益来自"并行"与"规模下降"，代价是"合并"这一步的开销。

**分治的适用条件**：子问题**相互独立**（不重叠）。如果子问题重叠，分治会做大量重复劳动——这正是动态规划要解决的。

### 10.4 主定理：估算分治复杂度

对于形如 `T(n) = a·T(n/b) + f(n)` 的递推式（拆成 a 个子问题，每个规模 n/b，合并代价 f(n)），有标准的估算法则。

直觉版本：

| 情形 | 结论 |
|------|------|
| 子问题很多、每层代价接近 | 复杂度由**分叉与深度**决定，形如 O(n^log_b a) |
| 每层代价均衡 | 形如 O(n log n)（如归并排序：a=2, b=2） |

**不必背公式，记住两个例子即可**：二分查找是 O(log n)，归并排序是 O(n log n)。这两个覆盖了绝大多数日常场景。

### 10.5 回溯：递归版的"试错"

**回溯（Backtracking）** 是分治的兄弟：在解空间里逐步构建候选解，一旦发现不可能成功就**撤销这一步**，回到上一个选择点。

```
选择 → 前进 → 若可行则继续，否则撤销并换下一个选择
```

| 经典问题 | 说明 |
|----------|------|
| N 皇后 | 逐行放皇后，冲突则回溯 |
| 数独求解 | 空格填数，矛盾则回退 |
| 全排列 / 子集枚举 | 依次选取与撤销 |
| 迷宫寻路 | 走不通就退回岔口 |

**生活类比**：**走迷宫**。走到死胡同就退回上一个岔路口，换另一条路——这比"站在入口把整张迷宫图算一遍"更贴近人的实际做法。

## 第十一章 动态规划：不重复做已经做过的事

### 11.1 从一个经典问题说起

**爬楼梯**：每次可以走 1 阶或 2 阶，走到第 n 阶有多少种走法？

朴素递归会产生大量重复计算（算 f(5) 时 f(3) 被算了两次，f(2) 被算了三次……），复杂度是指数级的。

而如果**把算过的答案记下来**，复杂度立刻降到 O(n)：

```
f(1) = 1
f(2) = 2
f(n) = f(n-1) + f(n-2)
```

这个"记下来"的动作叫**记忆化（memoization）**，它就是动态规划的核心。

### 11.2 动态规划的两个前提

**动态规划（Dynamic Programming, DP）** 由 Richard Bellman 在 1950 年代提出。"Programming"在这里是"规划/表格法"的意思，**与写代码无关**。

能用 DP 的问题需满足两个性质：

| 性质 | 含义 |
|------|------|
| **最优子结构** | 大问题的最优解由子问题的最优解组成 |
| **重叠子问题** | 子问题会被反复用到（否则分治就够了） |

### 11.3 两种实现风格

| 风格 | 做法 | 优点 |
|------|------|------|
| 自顶向下（记忆化递归） | 按需要递归，结果缓存 | 写起来贴近递推式，只算用到的状态 |
| 自底向上（填表） | 先算小规模，逐步推到大 | 无递归开销，便于做空间压缩 |

两者**本质等价**，都靠"缓存"避免重复计算。

### 11.4 解题四步法

```
① 定义状态：dp[i] 到底表示什么？（最容易出错的一步）
② 写出转移方程：dp[i] 如何由更小的状态得到
③ 确定边界与初始化
④ 确定计算顺序（保证用到的状态已经算好）
```

**90% 的 DP 困难都卡在第一步**——状态定义不清，后面全乱。

### 11.5 经典 DP 问题

| 问题 | 状态定义 | 复杂度 |
|------|----------|--------|
| 爬楼梯 | 到第 i 阶的走法数 | O(n) |
| 斐波那契数列 | 第 i 项的值 | O(n) |
| 背包问题 | 前 i 件物品、容量 j 下的最大价值 | O(n·W) |
| 最长公共子序列（LCS） | 前 i、前 j 个字符的 LCS 长度 | O(n·m) |
| 最长递增子序列（LIS） | 以第 i 个元素结尾的 LIS 长度 | O(n log n)（优化版） |
| 编辑距离 | 把前 i 个字符变成前 j 个字符的最少操作数 | O(n·m) |
| 最短路径（Floyd） | 允许经过前 k 个点的最短距离 | O(n³) |

**背包问题的重要性**：它是"资源有限、如何取舍"的原型。预算分配、库存决策、投资组合都有它的影子。

**编辑距离的日常应用**：输入法的"你是不是想输入……"、拼写纠错、DNA 序列比对。它衡量的是"最少几步改动能把一个字符串变成另一个"。

### 11.6 "带备忘录的暴力搜索"

一个非常实用的观念转变：

> **动态规划 ≈ 暴力搜索 + 备忘录**

遇到看似复杂的计数或最优化问题，先想"暴力枚举所有可能怎么做"，再看"哪些子问题被重复算了"，加缓存即可。这比直接硬想状态方程更易上手。

### 11.7 分治、贪心、DP 三者的关系

| 方法 | 子问题关系 | 是否回退/考虑全局 | 适用条件 |
|------|------------|-------------------|----------|
| 分治 | 相互独立 | 各自独立求解后合并 | 子问题不重叠 |
| 贪心 | 只看当前最优 | 不回退 | 贪心选择性质成立 |
| 动态规划 | **重叠** | 考虑所有子问题的最优 | 最优子结构 + 重叠子问题 |

**一张图记住**：

```
子问题会重复吗？
   │
   ├─ 不会 → 分治（如果还能拆）
   │
   └─ 会 → 每个子问题的最优能独立决定全局最优吗？
              │
              ├─ 能 → 贪心
              │
              └─ 不能 → 动态规划
```

## 第十二章 贪心算法与其它思想

### 12.1 贪心：每一步都选当下最好的

**贪心算法（Greedy Algorithm）** 每一步都做出当前看起来最优的选择，且**从不回头**。

| 优点 | 风险 |
|------|------|
| 通常很简单、很快 | 局部最优不一定等于全局最优 |

**贪心能成功的两个条件**：

1. **贪心选择性质**：每一步的局部最优选择，能导向全局最优；
2. **最优子结构**：与 DP 相同。

**反例——找零问题**：硬币面额为 {1, 3, 4}，要找 6 元。贪心会先拿 4，剩 2 只能拿两个 1，共 3 枚；而最优解是 3 + 3，只有 2 枚。**贪心在这里失效。**

但如果面额是 {1, 5, 10, 25} 这种"规范"体系，贪心找零恰好最优——**同一策略在不同结构下结论完全不同**。

### 12.2 经典贪心问题

| 问题 | 贪心策略 | 备注 |
|------|----------|------|
| 活动选择 | 每次选结束最早的 | 可证最优 |
| 区间调度 | 按结束时间排序后贪心 | 会议室安排 |
| 最小生成树（Kruskal/Prim） | 每次加最便宜的边 | 可证最优 |
| 霍夫曼编码 | 每次合并频率最低的两个 | 数据压缩 |
| Dijkstra | 每次扩展当前最近的 | 非负权可证最优 |
| 找零（规范面额） | 每次取最大面额 | 依赖面额体系 |

**霍夫曼编码**值得单独一提：它按字符出现频率构造不同长度的编码，高频字符用短码，低频用长码——这是无损压缩的基础之一，日常的 ZIP、JPEG 等格式都用到类似思想。

### 12.3 其它重要思想

| 思想 | 核心 | 例子 |
|------|------|------|
| 双指针 | 两个指针相向/同向移动 | 有序数组两数之和、去重、滑动窗口 |
| 滑动窗口 | 维护一个"窗口"，滑动并更新 | 最长无重复子串、最小覆盖子串 |
| 二分答案 | 对答案空间二分，验证可行性 | 最小容量、最大速度 |
| 位运算 | 用二进制位表示集合、并行计算 | 状态压缩、权限标志 |
| 并查集 | 高效维护"分组与合并" | 连通性、Kruskal |
| 前缀和 | 预处理累计值，使区间查询 O(1) | 区间和、子数组统计 |
| 单调栈/队列 | 维护单调性，求"下一个更大元素" | 柱状图最大矩形、滑动窗口最值 |

**双指针对照记忆**：对撞双指针（一个从头、一个从尾，向中间靠）用于有序数据的配对与收缩；快慢双指针（一慢一快）用于检测环、找中点、去重。

### 12.4 该用哪个思想：一张决策表

| 问题特征 | 优先考虑 |
|----------|----------|
| 数据有序，要配对/收缩区间 | 双指针 |
| 连续子数组/子串 | 滑动窗口、前缀和 |
| "最少/最大"且每步选择影响后续 | 动态规划 |
| "最少/最大"且局部最优可证成立 | 贪心 |
| 需要枚举所有方案 | 回溯 |
| 答案单调、要求最小可行值 | 二分答案 |
| 关系与分组 | 图论、并查集 |

**没有"最好的算法思想"，只有"最匹配问题结构的那个"。**

## 第十三章 复杂度的边界：P 与 NP

### 13.1 两类问题的分水岭

| 类别 | 含义 |
|------|------|
| **P** | 能在多项式时间内**求解**的问题 |
| **NP** | 能在多项式时间内**验证**一个给定解的问题 |

**验证 vs 求解是关键区别**：

- **数独**：给一个填好的答案，你几秒钟就能验证对不对（在 NP 里）；但从空盘开始解呢？已知的通用算法都是指数级的。
- **旅行商问题（TSP）**：给一条路线，很容易算出总长（验证）；但要找**最短**的那条，目前没有多项式算法。

**P ⊆ NP** 是显然的（能快速求解，自然能快速验证）。而 **P = NP 吗？** 这是计算机科学最著名、也是最悬而未决的问题。

### 13.2 NP 完全：最难的那批

**NP 完全（NP-Complete）** 问题是 NP 中"最难的"一类：如果其中**任何一个**能被多项式时间求解，那么**所有** NP 问题都能——也就意味着 P = NP。

| 里程碑 | 人物与时间 |
|--------|------------|
| 库克定理：SAT 是 NP 完全的 | Stephen Cook，1971 |
| 21 个问题的 NP 完全性证明 | Richard Karp，1972 |
| P vs NP 列为千禧年数学难题之一 | Clay 数学研究所，2000 |

> 来源：Cook, S. A., "The Complexity of Theorem-Proving Procedures", 1971（STOC）；Karp, R. M., "Reducibility Among Combinatorial Problems", 1972。Cook 于 1982 年获图灵奖，Karp 于 1985 年获图灵奖。P vs NP 被 Clay 数学研究所列为七个千禧年大奖难题之一（2000 年）。

**归约（reduction）** 的思想是这一切的核心：如果能证明"解决问题 B 的算法也能顺便解决问题 A"，那么 B 至少和 A 一样难。Karp 用这一招把 21 个问题串成了"同难联盟"。

### 13.3 面对 NP 完全问题怎么办

理论上"无解"，工程上自有出路：

| 策略 | 做法 | 适用 |
|------|------|------|
| 近似算法 | 给出有保证的"接近最优" | 结果精度可放宽 |
| 启发式算法 | 用经验规则快速得到好解（不保证最优） | 工程实用 |
| 参数化算法 | 复杂度只与某个小参数相关 | 参数确实很小 |
| 特殊情形 | 限制输入形态使其多项式可解 | 输入有结构 |
| 小规模精确解 | 输入规模小时直接穷举 | n 很小 |

**生活类比**：**装箱**。理论上"用最少箱子装完所有物品"是 NP 难的，但快递公司不会因此停止发货——他们用启发式规则（先装大的、按体积排序）在几毫秒内给出一个"足够好"的方案。

### 13.4 复杂度理论的实际意义

| 意义 | 说明 |
|------|------|
| 避免徒劳 | 知道问题属于 NP 完全，就不会执着于找多项式精确解 |
| 指导选型 | 判断该用精确算法还是近似/启发式 |
| 识别伪装 | 很多业务问题其实是熟面孔的 NP 难问题 |
| 理解安全 | 密码学的安全性正建立在"某些问题很难解"之上 |

> 延伸：RSA 依赖大整数分解很难，ECC 依赖椭圆曲线离散对数很难——一旦这些问题的多项式算法被找到（或量子计算机足够强），密码体系就需迁移。这与《数据安全与隐私保护》第三章的"后量子密码"呼应。

## 第十五章 常见误区与 FAQ

**Q1：复杂度越低一定越快吗？**
不一定。大 O 只描述趋势。n 很小时，"常数更小的高阶算法"可能反而更快。**理论用于判断量级，实测用于决定取舍。**

**Q2：O(n log n) 是排序的最优吗？**
对**基于比较**的排序，Ω(n log n) 是已被证明的下界。但计数排序、基数排序等**非比较排序**可以在特定前提（值域有限）下更快。

**Q3：哈希表查找是 O(1)，那是不是万能？**
不是。它不支持范围查询（"找出所有 18—25 岁的用户"），最坏情况会退化，且需要额外空间。范围查询要用有序结构（B+ 树、跳表、平衡树）。

**Q4：递归一定比迭代慢吗？**
通常有栈帧开销，但不绝对。现代编译器能做优化；更重要的是**可读性**——树与图的问题用递归往往清晰得多。

**Q5：为什么快排是"最快"，教科书却说它最坏 O(n²)？**
因为实测常数小、缓存友好，配合随机化后最坏情况几乎不会出现。工程实现还会混合堆排序保证最坏可控。

**Q6：动态规划和递归有什么区别？**
递归是**写法**，DP 是**策略**。"带记忆化的递归"就是 DP 的一种实现。区别只在于**有没有避免重复计算**。

**Q7：贪心能不能用于所有最优化问题？**
不能。必须证明贪心选择性质成立。找零问题（面额 1、3、4）就是经典反例。

**Q8：学算法必须刷很多题吗？**
理解结构与思想比题量重要。建议按"数据结构 → 排序查找 → 分治/DP/贪心 → 图论"的顺序，每类吃透三五个代表题。

**Q9：P = NP 如果被证明会怎样？**
若 P = NP，许多目前"很难"的问题（如密码破解、最优调度）将变成可高效求解，密码学基础会受到根本性冲击。目前学界普遍**猜测 P ≠ NP**，但尚无证明。

**Q10：这些知识在实际工作中用得上吗？**
用得上的不是"手写快排"，而是**判断该用哪种结构**、**估算方案会不会撑不住数据量**、**识别问题属于哪个复杂度级别**。

## 小结

- **算法**是"有限的解题步骤"，**程序**是它的实现；Wirth 的"程序 = 数据结构 + 算法"提醒我们二者一体两面——**换容器，复杂度可能从 O(n²) 降到 O(n)**。
- **大 O** 是衡量增长的尺子：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)。数据量越大，量级差异越致命。
- 基础容器各有取舍：**数组**随机访问快、中间增删慢；**链表**相反；**栈**后进先出、**队列**先进先出；**哈希表**平均 O(1) 但不支持范围查询。
- **树**表达层次关系：BST 会退化，平衡树与 **B+ 树**解决它（数据库索引的基石）；**堆**服务优先队列；**Trie** 服务前缀匹配。
- **图**描述关系：邻接表适合稀疏图，BFS/DFS 是基础遍历；**Dijkstra（1959）** 解决非负权最短路，**最小生成树**解决"最低成本连通"。
- **排序**的下界是 Ω(n log n)（比较模型下）；**非比较排序**可在特定前提突破。**二分查找**的 O(log n) 让十亿条数据只需约 30 次比较。
- 三种思想工具各有适用条件：**分治**要求子问题独立，**动态规划**处理重叠子问题，**贪心**需要可证明的局部最优性。
- 理论上存在难以逾越的边界：**P 与 NP** 之争、**NP 完全**问题（Cook 1971、Karp 1972）。工程上的应对是近似、启发式与利用输入特殊性。
