# 互联网与网络协议

> 子类：计算机与AI ｜ 难度：成人通识 ｜ 阅读时长：约 28 分钟

## 导语

你有没有想过：在深圳发一条微信给纽约的朋友，信息是怎么在不到一秒内跨越太平洋的？为什么输入 `www.baidu.com` 就能打开网页，而机器之间只认数字？Wi‑Fi 和 5G 凭什么能让你在地铁里刷视频？

本篇把"互联网"拆开来讲。你会学到支撑整个网络的 **TCP/IP 协议族**，理解域名系统（DNS）如何把"网址"翻译成"门牌号"，看清 HTTP/HTTPS 怎样请求和传输网页，了解 Wi‑Fi（IEEE 802.11）与 5G（3GPP NR）这两种无线技术，以及 CDN 与云计算如何把内容"搬到"你家门口。技术事实均标注来源（如 `IETF RFC`、`IEEE`、`3GPP`、`NIST`）。

## 第一章 互联网到底是什么

### 1.1 一句话定义

互联网（Internet）是**全球互联的计算机网络之网络**——无数局域网、运营商网络通过标准协议连接在一起，形成一个覆盖地球的"网中之网"。

### 1.2 关键事实表

| 概念 | 说明 |
|------|------|
| 起源 | 1969 年 ARPANET（美国国防部高级研究计划局） |
| 核心协议 | TCP/IP（1980 年代成为标准） |
| 管理机构 | IETF 制定标准；ICANN/IANA 管理域名与 IP 地址 |
| 规模 | 数十亿台设备互联 |
| 文档形式 | RFC（Request for Comments，征求意见稿，IETF 发布） |

> 来源：IETF RFC 系列（如 RFC 791 IP、RFC 793 TCP）。RFC 自 1969 年起由 IETF 及相关组织发布，是互联网标准的正式载体。

## 第二章 TCP/IP：互联网的"通用语"

### 2.1 为什么需要协议

不同的电脑品牌、操作系统、硬件千差万别，要让它们互相听懂，就必须约定一套**共同规则**——这就是网络协议。互联网的主干协议族叫 **TCP/IP**（Transmission Control Protocol / Internet Protocol）。

### 2.2 四层模型（TCP/IP 模型）

| 层级 | 名称 | 职责 | 代表协议 |
|------|------|------|----------|
| 4 | 应用层 | 为用户程序提供网络服务 | HTTP、DNS、FTP、SMTP |
| 3 | 传输层 | 端到端可靠/快速传输 | TCP、UDP |
| 2 | 网际层 | 寻址与路由（把包送到哪） | IP |
| 1 | 网络接口层 | 在物理介质上收发比特 | Ethernet、Wi‑Fi |

> 对照：学术界常用 OSI 七层模型，而工程实践多用上表四层模型，二者本质描述同一件事。

### 2.3 IP：每台设备的"门牌号"

IP（网际协议，Internet Protocol）给每个联网设备分配一个地址。当前有两代：

| 版本 | 地址长度 | 示例 | 状态 |
|------|----------|------|------|
| IPv4 | 32 位 | 192.168.1.1 | 仍广泛使用，地址已枯竭 |
| IPv6 | 128 位 | 2001:db8::1 | 为解决地址不足而设计（RFC 2460） |

> 来源：IPv4 见 RFC 791（1981）；IPv6 见 RFC 2460（1998，后被 RFC 8200 更新）。

### 2.4 TCP：可靠的"快递员"

TCP（传输控制协议，RFC 793，1981）保证数据**不丢、不乱、不重**：

- **三次握手**建立连接；
- **序号与确认**确保按序到达；
- **重传机制**补上丢失的包；
- **流量控制/拥塞控制**防止网络被冲垮。

代价是稍慢、有开销，适合网页、邮件等"必须准确"的场景。

### 2.5 UDP：追求速度的"明信片"

UDP（用户数据报协议，RFC 768）不建立连接、不保证送达，但**快、开销小**，适合视频通话、游戏、直播等对实时性敏感、可容忍少量丢包的场景。

| 对比 | TCP | UDP |
|------|-----|-----|
| 连接 | 有（三次握手） | 无 |
| 可靠性 | 高（重传、排序） | 低（尽力而为） |
| 速度 | 较慢 | 快 |
| 用途 | 网页、文件、邮件 | 语音、视频、游戏 |

## 第三章 DNS：把"网址"翻译成"门牌号"

### 3.1 为什么需要 DNS

人记不住 `93.184.216.34` 这样的数字，但能记住 `example.com`。**DNS（域名系统，Domain Name System）** 就是互联网的"电话簿"，把域名解析成 IP 地址（RFC 1034、RFC 1035，1987）。

### 3.2 解析过程

```
你在浏览器输入 example.com
   │
   ▼
① 查本地缓存 → 有则直接返回
   │ 没有
   ▼
② 问递归解析器（通常是运营商或 8.8.8.8 等）
   │
   ▼
③ 问根服务器：".com 找谁？"
   ▼
④ 问 .com 顶级域服务器：example.com 找谁？
   ▼
⑤ 问权威服务器：返回真实 IP
   ▼
⑥ 浏览器用该 IP 发起访问
```

### 3.3 域名结构

| 部分 | 例子 | 说明 |
|------|------|------|
| 顶级域 TLD | .com / .cn / .org | 由 ICANN 管理 |
| 二级域 | example | 注册者拥有 |
| 子域 | www / mail | 自行配置 |

> 来源：DNS 概念与实现见 RFC 1034（概念）、RFC 1035（实现与规范），1987。

## 第四章 HTTP 与 HTTPS：网页是怎么传过来的

### 4.1 HTTP 是什么

HTTP（超文本传输协议，HyperText Transfer Protocol）是浏览器与网站服务器之间"要网页、给网页"的语言。你访问的每个网址前都有 `http://` 或 `https://`。

> 来源：HTTP/1.1 见 RFC 2616（1999，已作废），现由 RFC 9110（语义）、RFC 9112（语法）取代（2022）。HTTP/2 见 RFC 7540，HTTP/3（基于 QUIC）见 RFC 9000。

### 4.2 一次网页请求的生命周期

```
浏览器 ──GET /index.html──▶ 服务器
浏览器 ◀──200 OK + 网页内容── 服务器
```

- **请求方法**：GET（取）、POST（提交）、PUT、DELETE 等。
- **状态码**：200 成功、301 跳转、404 找不到、500 服务器错误。

### 4.3 HTTPS：给 HTTP 穿上"盔甲"

HTTPS = HTTP + TLS（传输层安全）。它在 TCP 之上加密通信，防止被窃听、篡改、冒充。

| 项目 | HTTP | HTTPS |
|------|------|-------|
| 加密 | 无 | 有（TLS） |
| 端口 | 80 | 443 |
| 安全性 | 明文，可被拦截 | 防窃听、防篡改、可验证身份 |
| 证书 | 不需要 | 需要 CA 签发的数字证书 |

> 来源：HTTP over TLS（即 HTTPS）见 RFC 2818（2000）；TLS 1.3 见 RFC 8446（2018）。TLS 1.2 见 RFC 5246，正逐步退役。

### 4.4 TLS 1.3 的关键改进

- **握手更快**：从 2 个往返缩短到 1 个（0‑RTT/1‑RTT）。
- **强制前向安全**：每次会话用临时密钥，旧密钥泄露也不影响历史通信。
- **砍掉不安全算法**：禁用 RC4、DES、3DES、静态 RSA 密钥交换等（RFC 8446）。

## 第五章 Wi‑Fi 与 5G：无线连接的两种范式

### 5.1 Wi‑Fi（IEEE 802.11）

Wi‑Fi 是基于 IEEE 802.11 系列标准的无线局域网技术，让你在办公室、家里通过路由器无线上网。

| 标准 | 发布年份 | 频段 | 最高速率（约） |
|------|----------|------|----------------|
| 802.11b | 1999 | 2.4 GHz | 11 Mbps |
| 802.11g | 2003 | 2.4 GHz | 54 Mbps |
| 802.11n (Wi‑Fi 4) | 2009 | 2.4/5 GHz | 600 Mbps |
| 802.11ac (Wi‑Fi 5) | 2013 | 5 GHz | 1+ Gbps |
| 802.11ax (Wi‑Fi 6) | 2021 | 2.4/5 GHz | 9.6 Gbps |
| 802.11be (Wi‑Fi 7) | 2024 起 | 多频段 | 数十 Gbps |

> 来源：IEEE 802.11 标准族（IEEE Standards Association）。Wi‑Fi 6（802.11ax）最终版于 2021 年批准，最高速率可达约 9.6 Gbps，采用 OFDMA 多址接入。

**Wi‑Fi 工作要点**：
- 通过**路由器**把有线网络转成无线信号；
- 使用 **CSMA/CA** 机制避免多设备同时抢信道；
- 2.4 GHz 覆盖远但慢、易干扰；5 GHz 快但穿墙差。

### 5.2 5G（3GPP NR）

5G 是第五代移动通信，由 **3GPP** 标准化，其空口技术称为 **NR（New Radio）**。Rel‑15 是 5G 的基础版本（非独立组网 NSA 于 2017 年 12 月冻结，独立组网 SA 于 2018 年 6 月冻结）。

| 维度 | 说明 |
|------|------|
| 标准组织 | 3GPP（NR，Release 15 起） |
| 频段 | FR1（< 7 GHz，Sub‑6）与 FR2（24.25–52.6 GHz，毫米波） |
| 峰值速率 | 下行最高约 20 Gbps（FR2） |
| 关键技术 | 大规模 MIMO、波束赋形、灵活子载波间隔（15–240 kHz） |
| 三大场景 | eMBB（增强移动宽带）、URLLC（超低时延高可靠）、mMTC（海量物联） |

> 来源：3GPP TS 38.300（NR 总体描述）；5G NR 在 Rel‑15 由 3GPP 冻结。

**5G 与前代对比**：

| 代际 | 典型速率 | 时延 | 代表应用 |
|------|----------|------|----------|
| 3G | 数百 Kbps–数 Mbps | 百毫秒级 | 移动网页 |
| 4G LTE | 数十–数百 Mbps | 数十毫秒 | 视频、社交 |
| 5G | 数百 Mbps–数 Gbps | 目标 1 ms | 自动驾驶、工业互联网 |

### 5.3 Wi‑Fi 与 5G 怎么选

- **Wi‑Fi**：固定场所、低成本、靠路由器；流量走你家宽带。
- **5G**：移动场景、广覆盖、靠运营商基站；走蜂窝网络。
- 二者互补：手机在户外用 5G，回家自动切 Wi‑Fi。

## 第六章 CDN：把内容"搬到"你家门口

### 6.1 CDN 是什么

CDN（内容分发网络，Content Delivery Network）是一组**地理上分散的服务器**，把网站内容缓存到离用户更近的地方，从而加快加载、降低源站压力（IBM、Akamai、F5 等厂商定义一致）。

### 6.2 三大角色

| 角色 | 作用 |
|------|------|
| 源站（Origin） | 存放内容原始版本，是"真相之源" |
| 边缘节点（Edge/PoP） | 分布各地的缓存服务器，就近服务用户 |
| DNS | 把用户引导到最近的边缘节点 |

### 6.3 工作流程

```
用户请求 www.site.com/logo.png
   │
   ▼
DNS 解析 → 返回最近边缘节点 IP
   │
   ▼
边缘节点查缓存：
  命中（Cache Hit）→ 直接返回（最快）
  未命中（Miss）  → 回源站取，存一份再返回
```

### 6.4 CDN 带来的好处

| 好处 | 说明 |
|------|------|
| 更快 | 距离短，延迟低 |
| 省带宽 | 源站少传重复内容 |
| 更稳 | 抗流量高峰、抗单点故障 |
| 更安全 | 多数 CDN 提供 DDoS 防护 |

> 来源：CDN 概念由 Akamai、IBM、F5 等厂商与 IETF 相关文档共同定义；边缘节点也称 PoP（Point of Presence）。

## 第七章 云计算基础：算力变成"水电"

### 7.1 什么是云计算

云计算是按需使用远程数据中心的算力、存储与服务的模式。NIST（美国国家标准与技术研究院）给出权威定义：

> "云计算是一种模型，能按需、便捷地通过网络访问可配置的计算资源池（如网络、服务器、存储、应用、服务），这些资源可快速供给和释放，管理开销极小。"
> —— NIST SP 800‑145（Peter Mell & Tim Grance）

### 7.2 五大基本特征

| 特征 | 含义 |
|------|------|
| 按需自助服务 | 用户自己开通资源，无需人工 |
| 泛在网络访问 | 用手机、电脑等任意终端都能访问 |
| 资源池化 | 多用户共享资源，按需动态分配 |
| 快速弹性 | 随时扩容/缩容，像水电一样 |
| 可计量服务 | 用多少算多少，自动计费 |

### 7.3 三种服务模型

| 模型 | 英文 | 你管什么 | 典型例子 |
|------|------|----------|----------|
| 软件即服务 | SaaS | 只管用 | 网页邮箱、在线文档 |
| 平台即服务 | PaaS | 管应用 | 应用托管平台 |
| 基础设施即服务 | IaaS | 管系统/应用 | 云服务器、云硬盘 |

### 7.4 四种部署模型

| 部署 | 说明 |
|------|------|
| 公有云 | 面向大众，厂商运营（如阿里云、AWS） |
| 私有云 | 一家企业专用 |
| 社区云 | 多个有共同诉求的组织共享 |
| 混合云 | 以上组合，数据可互通 |

> 来源：NIST SP 800‑145《The NIST Definition of Cloud Computing》；SP 500‑322 服务分类指南。

### 7.5 云计算与上文的关系

- **CDN** 是云计算在网络分发上的延伸；
- 你玩的**云游戏**、用的**网盘**、开的**视频会议**，背后都是数据中心里成排的服务器；
- 5G 提供"最后一公里的无线管道"，云提供"管道那头的计算力"。

## 第九章 常见误区与 FAQ

| 误区 | 真相 |
|------|------|
| "5G Wi‑Fi"就是 5G 网络 | 错。路由器标的"5G"指 5 GHz 频段，和移动通信 5G 完全不同 |
| 关掉 Wi‑Fi 就不用流量了 | 错。Wi‑Fi 关后手机会切蜂窝数据，仍可能走流量 |
| HTTPS 的网站一定安全 | 不一定。HTTPS 只保证传输加密，不保证网站本身可信 |
| IP 地址是固定的 | 多数家庭是动态 IP，每次拨号可能变化 |
| 网速慢一定是运营商问题 | 可能是 Wi‑Fi 干扰、路由器老旧、设备或网线瓶颈 |

**Q：什么是公网 IP 和内网 IP？**
A：家里所有设备共享一个公网 IP（运营商给的），内部用 192.168.x.x 等私有地址（RFC 1918），靠路由器做地址转换（NAT）。

**Q：IPv6 为什么重要？**
A：IPv4 地址约 43 亿个，早就不够用了；IPv6 地址多到"每粒沙子都能分一个"，是物联网时代的基础。

## 第八章补充 数据包如何"旅行"：路由与 BGP

### 8.1 路由器像"十字路口"

互联网不是一根大管子，而是由无数**路由器（Router）**连成的网状结构。每个数据包从源到目的地，中间可能经过十几个甚至几十个路由器。每台路由器查自己的"路由表"，决定下一跳往哪走。

### 8.2 路由协议

| 协议 | 作用范围 | 说明 |
|------|----------|------|
| OSPF / IS‑IS | 内部（同一个网络） | 自动计算最短路径 |
| BGP | 跨网络（互联网级） | 不同运营商之间"交换可达性" |

> 来源：BGP（边界网关协议）见 RFC 4271；OSPF 见 RFC 2328。BGP 被称为"让互联网连在一起的胶水"，一次配置错误可能让整个国家短暂"断网"。

### 8.3 为什么有时"绕远路"

数据包走哪条路取决于路由策略、成本与拥堵，并不一定是地理最短。跨国访问有时绕道第三国，就是这个原因。

## 第九章补充 网络安全基础：防火墙、VPN 与加密通道

### 9.1 防火墙

防火墙像"门卫"，按规则放行或拦截流量。常见：

- **包过滤**：看 IP/端口放行；
- **状态检测**：跟踪连接状态；
- **应用层防火墙（WAF）**：识别恶意网页请求。

### 9.2 VPN（虚拟专用网）

VPN 在公共互联网上"挖一条加密隧道"，让你像身处公司内网一样安全访问资源。原理上仍是前文讲的 TCP/IP + 加密（类似 HTTPS 的思路）。

### 9.3 为什么"公共 Wi‑Fi 有风险"

在咖啡店连免费 Wi‑Fi，若网站只用 HTTP（明文），同网段的人可能窃听你的账号密码。**对策**：只用 HTTPS 网站、开启 VPN、不在此类网络输入敏感信息。

### 9.4 拒绝服务攻击（DDoS）

攻击者用海量垃圾请求淹没服务器，使其无法服务正常用户。CDN 因分布式节点多，天然具备一定抗 DDoS 能力（见第六章）。

## 术语速查表

| 缩写 | 全称 | 一句话 |
|------|------|--------|
| IP | Internet Protocol | 设备门牌号与寻址规则 |
| TCP | Transmission Control Protocol | 可靠、有序、重传的传输（RFC 793） |
| UDP | User Datagram Protocol | 快但不保证送达（RFC 768） |

| HTTP | HyperText Transfer Protocol | 网页传输协议（RFC 9110） |
| HTTPS | HTTP over TLS | 加密版 HTTP（RFC 2818） |
| TLS | Transport Layer Security | 传输层加密（TLS 1.3 = RFC 8446） |
| Wi‑Fi | Wireless Fidelity | 无线局域网（IEEE 802.11） |
| 5G NR | New Radio | 第五代移动通信空口（3GPP Rel‑15） |
| CDN | Content Delivery Network | 就近分发的内容网络 |
| IaaS/PaaS/SaaS | 云三种服务模型 | 基础设施/平台/软件即服务（NIST） |
| BGP | Border Gateway Protocol | 互联网级路由（RFC 4271） |

## 小结

- 互联网靠 **TCP/IP 协议族**互联：IP 负责寻址、TCP 负责可靠、UDP 负责快速。
- **DNS（RFC 1034/1035）** 把域名翻译成 IP，是互联网的电话簿。
- **HTTP/HTTPS** 传输网页，HTTPS 借助 **TLS 1.3（RFC 8446）** 实现加密与防窃听。
- **Wi‑Fi（IEEE 802.11）** 与 **5G（3GPP NR Rel‑15）** 是两种互补的无线技术。
- **CDN** 就近缓存内容、**云计算（NIST 定义）** 把算力变成按需取用的服务，二者共同构成现代互联网体验的底座。

### 十六、HTTP协议详解

**HTTP方法**：
- GET：获取资源
- POST：提交数据
- PUT：更新资源
- DELETE：删除资源

**HTTP状态码**：
- 2xx成功：200 OK, 201 Created
- 3xx重定向：301永久移动, 302临时移动
- 4xx客户端错误：400错误请求, 404未找到
- 5xx服务器错误：500内部错误, 503服务不可用

**HTTP/2改进**：
- 多路复用：并行传输多个请求
- 头部压缩：减少冗余头部
- 服务器推送：主动发送资源

**HTTP/3**：
- 基于QUIC协议（UDP）
- 更快的连接建立
- 更好的拥塞控制

### 十七、TCP/IP协议栈

**TCP三次握手**：
1. 客户端发送SYN
2. 服务器回复SYN+ACK
3. 客户端发送ACK

**TCP四次挥手**：
1. 主动方发送FIN
2. 被动方回复ACK
3. 被动方发送FIN
4. 主动方回复ACK

**TCP拥塞控制**：
- 慢启动：指数增长窗口
- 拥塞避免：线性增长窗口
- 快速重传：收到3个重复ACK立即重传
- 快速恢复：避免慢启动

**UDP特点**：
- 无连接：不需要建立连接
- 不可靠：不保证交付
- 低延迟：适合实时应用
- 应用：DNS、视频流、游戏

> 来源：RFC 791/793/768/2616/9110/9000；《计算机网络》教材

## 十七、更多网络协议详解

### 17.1 ICMP协议

**ICMP（Internet Control Message Protocol）** 是网络层的控制协议，用于报告错误和测试连通性。

| 功能 | 说明 | 应用 |
|------|------|------|
| **错误报告** | 目标不可达、超时等 | ping命令 |
| **网络诊断** | traceroute跟踪路径 | 路由分析 |
| **拥塞控制** | 源抑制消息 | 流量控制 |
| **路由重定向** | 优化路由表 | 网络优化 |

> 来源：RFC 792（1981）

### 17.2 ARP协议

**ARP（Address Resolution Protocol）** 用于将IP地址解析为MAC地址。

| 特点 | 说明 |
|------|------|
| **工作层** | 数据链路层 |
| **缓存机制** | ARP表存储映射关系 |
| **广播请求** | 询问"谁有这个IP" |
| **单播响应** | "我是，我的MAC是..." |

> 来源：RFC 826（1982）

### 17.3 DHCP协议

**DHCP（Dynamic Host Configuration Protocol）** 自动分配IP地址。

| 步骤 | 说明 |
|------|------|
| **发现** | 客户端广播"谁能给我IP" |
| **提供** | 服务器回复"我给你这个IP" |
| **请求** | 客户端确认"我要这个IP" |
| **确认** | 服务器确认"给你用" |

> 来源：RFC 2131（1997）

## 三十、网络故障排查

### 30.1 常见故障类型

| 故障 | 症状 | 可能原因 |
|------|------|----------|
| **无法连接** | 无网络访问 | 网线、路由器、ISP |
| **速度慢** | 加载缓慢 | 带宽不足、拥塞 |
| **间歇性断线** | 时有时无 | 信号干扰、硬件故障 |
| **高延迟** | 游戏卡顿 | 路由问题、服务器距离 |

| **ipconfig** | 查看IP配置 | ipconfig /all |
| **netstat** | 网络连接状态 | netstat -an |
