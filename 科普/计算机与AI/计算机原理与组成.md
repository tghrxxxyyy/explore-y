# 计算机原理与组成

> 子类：计算机与AI ｜ 难度：成人通识 ｜ 阅读时长：约 25 分钟

## 导语

我们每天用手机刷视频、用电脑写文档、用智能音箱听歌，但很少有人停下来问一句：**屏幕上的一切，到底是怎么"算"出来的？** 计算机看似无所不能，本质上却只做三件事：把信息变成二进制、按照指令一步步处理、再把结果变回我们能看见的文字和图像。

本篇带你从零认识计算机。你会读到 1945 年那份改变世界的报告如何奠定了今天所有电脑的"骨架"（冯·诺依曼架构），会明白 CPU 与 GPU 为何长得像却性格迥异，会弄清楚内存、硬盘、U 盘到底有什么区别，也会对操作系统这个"大管家"有清晰的概念。通篇尽量通俗，但关键事实均标注来源（如 `von Neumann, 1945`、`IEEE`、`NIST`），方便延伸阅读。

## 第一章 计算机的来历：从算盘到"通用机器"

### 1.1 计算工具简史

| 时期 | 代表工具 | 特点 |
|------|----------|------|
| 古代 | 算盘、计算尺 | 纯机械，依赖人脑操作规则 |
| 1642 | 帕斯卡加法器 | 第一台机械加法机（Blaise Pascal） |
| 1837 | 巴贝奇分析机 | 提出"程序控制"雏形（Charles Babbage） |
| 1936 | 图灵机模型 | 从理论上证明"通用计算机"的可能性（Alan Turing） |
| 1946 | ENIAC | 第一台通用电子计算机，使用约 1.8 万只真空管 |
| 1945 | EDVAC 报告 | 提出"存储程序"概念，奠定现代架构（von Neumann, 1945） |

> 来源：von Neumann, J. *First Draft of a Report on the EDVAC*, 1945（宾夕法尼亚大学摩尔学院，6 月 30 日）。

### 1.2 关键转折：存储程序概念

在 ENIAC 时代，要换一个计算任务，工程师需要手动重新接线、拨动开关，耗时数小时。1945 年，约翰·冯·诺依曼（John von Neumann）在《EDVAC 报告草案》中提出：**程序指令和数据应当一样，存放在同一个内存里**，计算机自己按顺序读取并执行。这就是"存储程序"（stored-program）思想，今天几乎所有的电脑都遵循这一范式（von Neumann, 1945）。

> 注：存储程序概念的归属在学界有争议，莫奇利（Mauchly）与埃克特（Eckert）等工程师同样作出了奠基性贡献；图灵 1936 年的"通用机"理论也早已预示了这一方向。

## 第二章 冯·诺依曼架构：现代电脑的"骨架"

### 2.1 五大部件

冯·诺依曼架构把一台计算机划分为五个逻辑部分（von Neumann, 1945）：

- **运算器（CA，Central Arithmetic）**：负责加减乘除等算术运算。
- **控制器（CC，Central Control）**：指挥各部件按指令顺序工作。
- **存储器（M，Memory）**：存放程序和数据。
- **输入设备（I，Input）**：把外部信息送进计算机（键盘、鼠标等）。
- **输出设备（O，Output）**：把结果呈现给人（屏幕、打印机等）。

```
        ┌──────────┐
        │  输入 I   │──┐
        └──────────┘  │
                       ▼
                ┌──────────────┐
                │   存储器 M    │◄──────┐
                └──────────────┘       │
                       ▲               │
          ┌────────────┴───────┐       │
          │  控制器 CC + 运算器 CA │──────┘
          └─────────────────────┘
                       │
        ┌──────────┐   │
        │  输出 O   │◄──┘
        └──────────┘
```

### 2.2 "冯·诺依曼瓶颈"

由于指令和数据共用同一条总线（数据通路），CPU 取指令和取数据不能同时进行，这被称为**冯·诺依曼瓶颈**。现代计算机用缓存（Cache）、指令流水线等技术缓解它，但根本结构未变。

### 2.3 对比：哈佛架构

| 项目 | 冯·诺依曼架构 | 哈佛架构 |
|------|--------------|----------|
| 指令/数据存储 | 同一内存 | 分开的内存 |
| 典型应用 | 个人电脑、服务器 | 单片机、DSP、部分嵌入式 |
| 优点 | 结构统一、灵活 | 取指取数并行、速度快 |
| 缺点 | 瓶颈明显 | 硬件更复杂 |

## 第三章 二进制：计算机的唯一语言

### 3.1 为什么是 0 和 1？

电子器件最稳定的状态是"通电/断电""高电平/低电平"，正好对应两个状态。用二进制（base-2）表示信息，比用十进制更抗干扰、更易用电路实现。冯·诺依曼在 1945 年的报告中也明确指出系统应采用二进制记数法（von Neumann, 1945）。

### 3.2 基本单位

| 单位 | 含义 |
|------|------|
| 位（bit） | 1 个二进制位，0 或 1，最小单位 |
| 字节（Byte） | 8 个 bit，可表示 0–255 |
| KB | 约 1000 字节（严格为 1024） |
| MB | 约 100 万字节 |
| GB | 约 10 亿字节 |
| TB | 约 1 万亿字节 |

> 注：存储厂商常用 10 进制（1 KB = 1000 B），操作系统常用 2 进制（1 KiB = 1024 B），所以"标称 512 GB 的硬盘"在系统里往往显示为约 476 GB，并非缩水。

### 3.3 数字、文字、图像如何变成 0/1

- **整数**：用补码表示负数（von Neumann 报告中已提出二补数思路）。
- **文字**：用编码表，如 ASCII（英文字符）、Unicode/UTF-8（覆盖全球文字）。
- **图像**：每个像素拆成红绿蓝（RGB）三个 0–255 的数值。
- **声音**：按固定频率采样，把波形转成数字序列。

**小练习**：字符 `A` 在 ASCII 中是十进制 65，二进制即 `01000001`。

## 第四章 CPU：计算机的大脑

### 4.1 CPU 由什么组成

CPU（中央处理器，Central Processing Unit）主要由运算器和控制器构成，内部还包括：

| 部件 | 作用 |
|------|------|
| 寄存器（Register） | 最快的临时存储，放当前正在算的数据 |
| 算术逻辑单元 ALU | 执行加减、比较、逻辑运算 |
| 控制单元 CU | 解码指令、发出控制信号 |
| 缓存 Cache | 靠近 CPU 的高速小容量内存 |

### 4.2 指令周期：CPU 的工作循环

CPU 永不停歇地重复"取指令 → 译码 → 执行 → 写回"四步（指令周期）。以 `1 + 2` 为例：

1. **取指令**：从内存读出"加法"指令。
2. **译码**：控制单元识别出这是加法操作。
3. **执行**：ALU 把两个操作数相加。
4. **写回**：把结果放回寄存器或内存。

现代 CPU 用**流水线**（让多条指令的不同阶段重叠执行）和**乱序执行**把单条指令的延迟"藏起来"，从而提升整体吞吐（见 CPU/GPU 对比章节）。

### 4.3 主频、核心与线程

| 概念 | 通俗解释 |
|------|----------|
| 主频（GHz） | 每秒能完成多少个基本节拍，越高通常越快 |
| 核心（Core） | 一个独立的运算单元，4 核可同时干 4 件事 |
| 线程（Thread） | 操作系统调度的"执行流"，超线程让 1 核模拟 2 线程 |
| 制程（nm） | 晶体管最小尺寸，越小越省电、越密 |

> 来源：CPU 微架构概念属计算机组成基本原理，详见 Hennessy & Patterson《计算机组成与设计》。

## 第五章 GPU：为"并行"而生的怪兽

### 5.1 CPU vs GPU：设计目标不同

| 维度 | CPU | GPU |
|------|-----|-----|
| 核心数 | 少（4–64 个，复杂强大） | 极多（数百到上万个，简单） |
| 设计目标 | 低延迟、强控制逻辑 | 高吞吐、大规模并行 |
| 缓存 | 大（L1/L2/L3 多级） | 小（贴近显存，靠海量线程掩盖延迟） |
| 擅长 | 操作系统、逻辑分支、串行任务 | 图形、矩阵运算、深度学习 |
| 时钟 | 3–5 GHz | 1–2.5 GHz |
| 内存带宽 | 约 50–100 GB/s | 1–3 TB/s（HBM 显存） |

> 来源：NVIDIA CUDA C++ Programming Guide；Hwu 等《Programming Massively Parallel Processors》。NVIDIA H100 含 132 个流式多处理器（SM），每 SM 64 核，合计约 8448 核。

### 5.2 为什么 AI 离不开 GPU？

训练一个神经网络要做天文数字的"乘加"运算（例如矩阵相乘）。CPU 核心少，算得慢；GPU 数千核心同时算，把吞吐拉满。NVIDIA A100 在 32 位精度下约 19.5 TFLOPS，而同期 24 核 Intel 处理器仅约 0.66 TFLOPS（Hwu 等，2021）。差距正是 AI 时代 GPU 崛起的根本原因。

### 5.3 SIMT 执行模型

GPU 把线程按 **warp**（NVIDIA 通常 32 个线程一组）调度，同一 warp 内所有线程执行同一条指令、但处理不同数据，称为 SIMT（单指令多线程）。当部分线程在等待数据时，GPU 立刻切换到其他 warp，让计算单元永不空闲——这是它"用海量线程换吞吐"的核心诀窍。

## 第六章 内存与存储：快与慢的金字塔

### 6.1 存储层次结构（金字塔）

越往上越快越贵、容量越小；越往下越慢越便宜、容量越大。

```
        寄存器 (1 周期)         ← 最快、最小
           ↓
        L1 / L2 / L3 缓存
           ↓
          内存 RAM (DRAM)       ← 你常说的"8G/16G 内存"
           ↓
        固态硬盘 SSD (NVMe)
           ↓
        机械硬盘 HDD
           ↓
      磁带 / 光盘 / 网盘        ← 最慢、最大、最便宜
```

### 6.2 内存（RAM）与存储（硬盘）的区别

| 项目 | 内存 RAM | 硬盘 SSD/HDD |
|------|----------|--------------|
| 是否掉电消失 | 是（易失性） | 否（非易失性） |
| 速度 | 极快（纳秒级） | 较慢（微秒到毫秒级） |
| 作用 | 放正在运行的程序和数据 | 长期保存文件、系统 |
| 容量 | 通常 8–64 GB | 通常 256 GB–数 TB |

> 关键理解：**内存像"工作台"，硬盘像"仓库"**。开机后，程序从硬盘被"搬"到内存才能运行；关机后内存清空，硬盘内容还在。

### 6.3 ROM、闪存与常见介质

| 类型 | 特点 | 例子 |
|------|------|------|
| ROM | 只读、固化 | 主板 BIOS |
| DRAM | 需刷新、用作内存 | 内存条 |
| NAND 闪存 | 非易失、可擦写 | SSD、U 盘、手机存储 |
| 机械硬盘 HDD | 磁道旋转、便宜大容量 | 台式机仓库盘 |

## 第七章 操作系统：计算机的"大管家"

### 7.1 操作系统做什么？

操作系统（OS，Operating System）是介于硬件与应用之间的系统软件，核心职责：

- **进程管理**：决定哪个程序先用 CPU（调度）。
- **内存管理**：给每个程序分配内存、防止互相踩踏。
- **文件系统**：把你存的照片、文档组织成目录。
- **设备驱动**：让显卡、打印机等硬件能被统一调用。
- **用户接口**：提供图形界面（GUI）或命令行（CLI）。

### 7.2 主流操作系统对比

| 系统 | 主要场景 | 特点 |
|------|----------|------|
| Windows | 个人电脑主流 | 软硬件生态丰富 |
| macOS | 苹果电脑 | 与苹果硬件深度整合 |
| Linux | 服务器、开发者 | 开源、稳定、可定制 |
| Android / iOS | 手机 | 移动端主导 |

> 来源：操作系统概念属经典教材范畴，参见 Silberschatz 等《操作系统概念》（*Operating System Concepts*）。

### 7.3 内核与用户态

操作系统内核（Kernel）拥有最高权限，直接管硬件；普通应用程序运行在"用户态"，想用硬件必须通过内核提供的接口（系统调用）。这种隔离保障了系统稳定与安全。

## 第八章 主板、总线与外设

### 8.1 主板：把所有部件连起来

主板（Motherboard）是一块印刷电路板，上面布满了：

- **CPU 插槽**
- **内存插槽**
- **芯片组（南桥/北桥）**：协调各部件通信
- **扩展槽（PCIe）**：插显卡、网卡等
- **各类接口**：USB、HDMI、音频等

### 8.2 总线：数据的高速公路

总线（Bus）是部件间传输数据的通道。常见：

| 总线/接口 | 用途 |
|-----------|------|
| PCIe | 显卡、高速扩展卡 |
| USB | 键鼠、U 盘等外设 |
| SATA / NVMe | 连接硬盘 |
| HDMI / DisplayPort | 连接显示器 |

### 8.3 输入与输出设备

- **输入**：键盘、鼠标、麦克风、摄像头、触控板。
- **输出**：显示器、音箱、打印机。
- **既能输入又能输出**：触摸屏、网卡（收发数据）。

## 第十章 指令集架构：CPU 的"方言"

### 10.1 什么是指令集（ISA）

前面说 CPU 执行"指令"，但不同厂家设计的 CPU 能听懂的指令并不完全相同。这种"CPU 与软件之间的契约"叫做**指令集架构（ISA, Instruction Set Architecture）**。同一套软件要能在不同硬件上运行，就必须遵循相同的 ISA。

### 10.2 两大阵营：CISC 与 RISC

| 类型 | 全称 | 特点 | 代表 |
|------|------|------|------|
| CISC | 复杂指令集 | 单条指令能做复杂操作，历史兼容性强 | x86（Intel、AMD 个人电脑） |
| RISC | 精简指令集 | 指令简单统一，靠组合实现复杂功能，更省电高效 | ARM（手机）、RISC-V（开源） |

> 趋势：今天两者界限在模糊。x86 内部也会把复杂指令拆成微操作；ARM 也吸收了一些复杂特性。苹果自研芯片（Apple Silicon）采用 ARM 架构，在笔记本上兼顾性能与续航。

### 10.3 从机器码到高级语言

```
高级语言（Python/Java/C）
        │ 编译/解释
        ▼
汇编语言（add, mov, jmp…）   ← 人类可读的"助记符"
        │ 汇编器
        ▼
机器码（0/1 序列）            ← CPU 真正执行
```

你平时写的程序，最终都要翻译成 CPU 能懂的机器码。越接近硬件的语言（如 C、Rust）运行越快，越高级的语言（如 Python）开发越方便——这是"效率与易用"的经典权衡。

## 第十一章 计算机性能怎么衡量

### 11.1 常用指标

| 指标 | 含义 | 说明 |
|------|------|------|
| 主频 GHz | 每秒节拍数 | 单核快不快 |
| 核心数 | 并行单元数 | 能同时干几件事 |
| IPC | 每周期指令数 | 微架构效率 |
| FLOPS | 每秒浮点运算次数 | 科学计算/AI 算力单位（TFLOPS、PFLOPS） |
| 吞吐量 | 单位时间完成任务量 | 整体产能 |
| 延迟 | 单个任务响应时间 | 交互体验关键 |

### 11.2 阿姆达尔定律（Amdahl's Law）

加速一个系统，收益受限于"无法并行"的那部分。公式：

```
加速比 = 1 / ((1 - P) + P / N)
```

其中 `P` 是可并行比例，`N` 是处理器数量。即使 `N` 趋于无穷，加速比上限也只是 `1 / (1 - P)`。这解释了为什么**不是堆核心就一定能变快**——串行瓶颈决定了天花板。

> 来源：Gene Amdahl, *Amdahl's Law*, 1967。

### 11.3 基准测试（Benchmark）

为了让性能可比，业界用标准测试程序打分，例如：

- **CPU**：SPEC CPU、Geekbench、Cinebench
- **存储**：顺序/随机读写速度（MB/s、IOPS）
- **综合**：PCMark、3DMark

记住：**跑分只是参考，真实体验取决于你最常用软件的优化程度**。

## 第十二章 常见误区与 FAQ

### 12.1 误区澄清

| 误区 | 真相 |
|------|------|
| 内存越大电脑越快 | 内存够用后，再大对速度帮助有限；瓶颈可能在 CPU 或硬盘 |
| 电脑"越用越卡"是硬件老化 | 多为软件垃圾、后台进程、磁盘碎片/满载所致 |
| 关掉程序就等于释放了所有资源 | 部分程序会留后台服务，需彻底退出 |
| 格式化能彻底销毁数据 | 普通快速格式化只是标记可用，数据仍可恢复（需覆写） |
| 64 位比 32 位"快一倍" | 主要好处是可寻址更大内存，速度提升并非线性 |

### 12.2 常见问题

**Q1：手机算不算计算机？**
A：算。手机里是一颗"片上系统（SoC）"，集成了 CPU、GPU、基带等，同样遵循存储程序原理。

**Q2：为什么电脑关机后时间还在走？**
A：主板上有一块小电池（CMOS 电池）给实时时钟供电，断电也不丢。

**Q3：云电脑/云游戏里的"电脑"在哪？**
A：在远程数据中心的服务器上，通过网络把画面传给你（详见本系列《互联网与网络协议》云计算章节）。

**Q4：量子计算机会取代现在的电脑吗？**
A：短期内不会。量子计算擅长特定问题（如因数分解、模拟分子），经典计算机在通用任务上仍不可替代。

## 小结

- 今天的计算机大多遵循 **1945 年冯·诺依曼提出的"存储程序"架构**（运算器、控制器、存储器、输入、输出五大部件）。
- 计算机只认 **二进制（0/1）**，一切文字、图像、声音最终都被编码成 bit。
- **CPU** 擅长低延迟的串行与控制任务；**GPU** 擅长高吞吐的并行计算，是 AI 的算力基石。
- **内存易失、快而小；硬盘非易失、慢而大**，二者分工如同工作台与仓库。
- **操作系统**是管理硬件、服务应用的"大管家"，让我们不必直接面对电路。

下一篇《互联网与网络协议》将带你认识：这些独立的计算机会如何彼此对话，信息又如何在毫秒间跨越半个地球。

## 第十三章 CPU 流水线与缓存详解

### 13.1 指令流水线（Pipeline）

现代 CPU 将指令周期拆分为多级流水线，让多条指令的不同阶段重叠执行：

| 阶段 | 功能 |
|------|------|
| 取指（IF） | 从内存读取指令 |
| 译码（ID） | 识别指令类型和操作数 |
| 执行（EX） | ALU 运算或地址计算 |
| 访存（MEM） | 读写内存 |
| 写回（WB） | 结果存入寄存器 |

- 5 级流水线理论吞吐提升 5 倍（理想情况）。
- 现代 CPU 可达 14–20 级超深流水线（如 Intel Skylake 19 级）。
- **流水线冒险**：数据依赖（需转发/旁路）、控制依赖（需分支预测）、结构冲突（需资源复制）。

### 13.2 分支预测

CPU 在取指阶段猜测分支走向，提前执行。现代处理器预测准确率 >95%。预测失败需清空流水线，代价约 10–20 个时钟周期。

### 13.3 缓存层次结构

| 缓存 | 容量 | 延迟 | 说明 |
|------|------|------|------|
| L1 | 32–64 KB | ~1 周期 | 每核私有，分为指令/数据缓存 |
| L2 | 256 KB–1 MB | ~3–10 周期 | 每核私有 |
| L3 | 数 MB–数十 MB | ~20–50 周期 | 多核共享，统一缓存 |

- **缓存行（Cache Line）**：通常 64 字节，是缓存与内存间数据传输的最小单位。
- **缓存命中率**：L1 命中率 ~95%，L2 ~90%，综合命中率影响性能极大。
- **写策略**：写直达（简单但慢）vs 写回（快但需脏位管理）。

### 13.4 乱序执行（Out-of-Order Execution）

CPU 可将无依赖关系的指令提前执行，打破顺序以提高流水线利用率。需要**重排序缓冲区**和**寄存器重命名**支持。

> 来源：Hennessy & Patterson《计算机体系结构：量化研究方法》。

## 第十四章 并行计算基础

### 14.1 为什么需要并行

单核频率提升已遇物理瓶颈（功耗墙、散热墙），并行成为提升性能的主要途径。

### 14.2 并行类型

| 类型 | 说明 | 例子 |
|------|------|------|
| 指令级并行（ILP） | 单核内流水线、超标量、乱序执行 | 现代 CPU |
| 数据级并行（DLP） | 同一操作处理大量数据 | GPU、SIMD 指令 |
| 任务级并行（TLP） | 多核/多处理器同时执行不同任务 | 多核 CPU、分布式系统 |

### 14.3 GPU 并行计算模型

GPU 使用 SIMT（单指令多线程）模型：
- 线程按 **warp**（NVIDIA 为 32 线程）分组执行。
- 同一 warp 内执行相同指令，不同数据。
- 适合**数据并行**：图像处理、矩阵运算、深度学习。

### 14.4 分布式计算

多台计算机通过网络协作，典型架构：

| 架构 | 特点 |
|------|------|
| MPI（消息传递） | 节点间显式通信，适合 HPC |
| MapReduce/Spark | 大数据批处理框架 |
| 参数服务器 | 分布式深度学习训练 |

### 14.5 Amdahl 定律回顾

加速比 = 1 / ((1 − P) + P / N)，其中 P 为可并行比例，N 为处理器数。即使 N → ∞，加速比上限为 1/(1−P)。这解释了为什么**串行瓶颈是并行计算的天花板**。

> 来源：Gene Amdahl, 1967；NVIDIA CUDA 编程指南；《并行计算导论》。
