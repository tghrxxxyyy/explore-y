# 程序员 · 常见面试题（含国内大厂 / AI / 信创）
> 按方向分类的常考知识点清单，用于自查与复习。国内面试 = 八股 + 手撕算法 + 项目深挖 + 系统设计，AI/信创方向会加专项。
## 一、计算机基础
- **网络**：TCP 三次握手/四次挥手；HTTP 与 HTTPS 区别；HTTP/2 与 HTTP/3；状态码；DNS 解析；WebSocket；TLS 握手。
- **OS**：进程 vs 线程；死锁四条件与预防；虚拟内存；上下文切换；协程。
- **数据库**：索引为什么快（B+树）；事务 ACID 与隔离级别；脏读/幻读/不可重复读；MVCC；分库分表。
- **编译/运行**：JVM 内存模型与 GC（Java 岗必问）；Python GIL。
## 二、数据结构与算法（手撕重灾区）
- 数组/链表/栈/队列/哈希表特性与复杂度。
- 二叉树遍历、二叉搜索树、堆、红黑树（了解）。
- 排序：快排、归并、堆排的复杂度与稳定性。
- 动态规划、回溯、贪心、双指针、滑动窗口典型题。
- **高频**：LRU 缓存、两数之和、最长子串、二叉树层序、拓扑排序、背包。
- 刷题：LeetCode + 牛客网（国内校招/社招真题多）。
## 三、编程语言（Java / Python 为主，国内）
- **Java**：JMM 与 GC（G1/ZGC）；集合源码（HashMap）；并发（synchronized / volatile / 线程池）；JVM 调优。
- **Python**：GIL 是什么、装饰器、生成器与迭代器、内存管理、GIL 下并发方案（asyncio / 多进程）。
- **Go**：goroutine 调度、channel、内存模型（云原生/中间件岗常问）。
- **JS/TS**：事件循环、闭包、原型链、Promise、防抖节流、虚拟 DOM。
## 四、框架与工程
- 前端：虚拟 DOM diff、事件循环、hooks 原理、性能优化。
- 后端：RESTful / RPC（gRPC）设计、鉴权（JWT/Session/OAuth2）、幂等、分布式锁。
- 数据库：慢查询优化、索引最左前缀、覆盖索引、缓存穿透/击穿/雪崩、双写一致性。
- 消息队列：Kafka / RocketMQ 消费幂等、顺序、重复、积压。
- 微服务：服务注册发现、熔断限流（Sentinel）、链路追踪。
## 五、系统设计（高级/架构岗必问）
- 短链系统、限流（令牌桶/漏桶）、秒杀、Feed 流、排行榜、延迟队列。
- 高并发：缓存架构、读写分离、分库分表、热点 key。
- 高可用：熔断、降级、限流、异地多活（大厂常问）。
- 设计题套路：需求澄清 → 估算 QPS/存储 → 数据模型 → 接口 → 瓶颈与扩展。
- 书单：*Designing Data-Intensive Applications*、*数据密集型应用系统设计*。
## 六、AI / 大模型方向（2025+ 高频新考点）
- **基础**：Transformer 自注意力机制；预训练 vs 微调 vs 推理；RLHF/DPO；量化（INT8/FP8）。
- **RAG**：为什么能减幻觉？切片策略、Embedding 选型、向量库（Milvus/Chroma）、重排、引用溯源。
- **Agent**：工具调用、规划-执行、ReAct、多智能体、**MCP 协议**是什么。
- **微调**：SFT 数据构建、LoRA/QLoRA 原理、过拟合防范、评测集。
- **推理部署**：vLLM 是什么、KV Cache、吞吐优化、成本估算。
- **场景题**：「如何用 RAG 优化公司知识库检索？」「如何设计一个 Agent 客服？」「大模型微调要准备多少数据？」
## 七、信创 / 国产技术栈（银行/政务/国企岗常问）
- 国产数据库：达梦 DM / GaussDB 与 Oracle/MySQL 的差异、DMSQL/PL-pgSQL 迁移注意点。
- 国产 OS：统信 UOS / 麒麟 / OpenEuler 与 CentOS 的使用差异。
- 国产芯片：鲲鹏（ARM64）/ 飞腾 / 龙芯（LoongArch）架构与编译注意。
- 等保 2.0：分级、测评、备案流程；国密 SM2/SM3/SM4 的应用场景。
- 迁移题：「如何把一套 Spring Boot + MySQL 系统迁移到达梦 + 麒麟？」
## 八、鸿蒙开发（移动/ IoT 方向）
- ArkTS 与 TS 的区别；ArkUI 声明式 UI；一次开发多端部署。
- 鸿蒙应用上架、权限模型、分布式能力。
## 九、行为 / 软技能（几乎必问）
- 介绍一个你解决的最难问题（STAR 法则）。
- 需求变更如何沟通？线上故障如何排查（复盘模板）？
- 你为什么想做 AI/信创方向？未来 3 年规划？
- 35 岁相关（资深岗）：你的核心竞争力是什么？如何带人/做技术决策？

2. 数据模型与 API 设计

5. 瓶颈分析与优化
6. 扩展点（容灾、监控、灰度）
### 数据库面试题（MySQL + Redis）
**MySQL 常考**：
- **索引**：B+ 树结构、最左前缀原则、覆盖索引、索引下推、索引失效场景。
- **事务**：ACID 语义、四种隔离级别、MVCC 实现原理、当前读 vs 快照读。
- **锁**：行锁/表锁/间隙锁/临键锁、死锁排查与预防。
- **优化**：慢查询分析（EXPLAIN）、分库分表策略、主从复制原理、半同步复制。
- **新特性**：MySQL 8.0 窗口函数、JSON 类型、不可见索引。
**Redis 常考**：
- **数据结构**：String/List/Hash/Set/ZSet 内部编码、应用场景。
- **缓存策略**：穿透（布隆过滤器）、击穿（互斥锁）、雪崩（随机过期）。
- **持久化**：RDB vs AOF、混合持久化、数据恢复流程。
- **集群**：哨兵模式、Cluster 分片、数据迁移与扩缩容。
- **高级特性**：Lua 脚本、Pipeline 批量、发布订阅、Stream 消息队列。
### 网络面试题（TCP/IP 全链路）
- **TCP**：三次握手/四次挥手（状态机）、滑动窗口、拥塞控制（慢启动/快重传/快恢复）、TIME_WAIT 处理。
- **HTTP**：1.1 vs 2 vs 3 区别、Keep-Alive、分块传输、多路复用、QUIC 协议。
- **HTTPS**：TLS 1.2/1.3 握手流程、证书链验证、对称/非对称加密混合使用。
- **DNS**：递归/迭代查询、DNS 劫持与防劫持、HTTPDNS 原理。
- **WebSocket**：全双工通信、与 SSE 对比、心跳机制、断线重连。

### 操作系统面试题

- **进程/线程**：进程间通信（管道/共享内存/消息队列）、线程模型（1:1/N:1/N:M）。
- **内存管理**：虚拟内存、页表、TLB、页面置换算法（LRU/CLOCK）。
- **I/O 模型**：阻塞/非阻塞/IO 多路复用（select/poll/epoll）、零拷贝（sendfile）。
- **Linux 实战**：top/vmstat/iostat 命令、文件系统（ext4 vs xfs）、cgroup 资源隔离。

### 语言特性面试题

**Java 进阶**：
- **JVM**：内存结构、GC 算法（G1/ZGC）、类加载机制（双亲委派）、JVM 调优工具（jstat/jmap/jstack/Arthas）。
- **并发**：synchronized 原理（锁升级）、volatile 语义、AQS 原理、线程池参数含义与调优。
- **集合**：HashMap 扩容机制、ConcurrentHashMap 分段锁、LinkedHashMap LRU 实现。

**Go 进阶**：
- **调度**：GMP 模型、抢占式调度、sysmon 监控线程。
- **内存**：tcmalloc 内存分配、GC 三色标记、写屏障。
- **并发**：channel 底层实现、select 多路复用、sync.Pool 对象池。

**Python 进阶**：
- **GIL**：为什么有 GIL、GIL 释放时机、多进程 vs 多线程选型。
- **元编程**：元类、描述符协议、`__new__` vs `__init__`。
- **性能**：Cython/Numba 加速、内存分析（tracemalloc）、C 扩展。

## 十二、答题框架（STAR 法则进阶）

### 行为面试 STAR 框架
- **S（Situation）**：背景是什么？项目目标是什么？
- **T（Task）**：你的具体职责是什么？遇到了什么困难？
- **A（Action）**：你做了什么？为什么做这个选择？考虑了哪些替代方案？
- **R（Result）**：结果如何？量化数据（提升了 X%、节省了 Y 万元、减少了 Z 分钟）。

### 技术深挖三段式
1. **是什么**：用自己的话解释技术原理（别背定义，用类比）。
2. **为什么**：为什么选这个方案？对比过哪些替代方案？权衡了什么？
3. **怎么做**：具体怎么落地的？踩了什么坑？怎么解决的？

### 系统设计四步法
1. **澄清需求**：功能需求 + 非功能需求（QPS/延迟/可用性）+ 约束条件。
2. **高层设计**：画架构图、定义核心接口、确定数据模型。
3. **深入设计**：核心组件详细方案、存储选型、缓存策略、一致性保证。
4. **扩展讨论**：监控告警、灰度发布、容灾方案、未来演进。

### 被问不会时的应对
- **承认不知道**：「这个点我之前没有深入研究过，但我的理解是……」。
- **展示思考**：「根据我已有的知识，我猜测可能是……因为……」。
- **追问引导**：「我不确定这个细节，但我想知道在实际场景中，这个问题通常是……」。
- **绝对不要**：硬编答案、沉默超过 10 秒、转移话题。

## 十三、面试复盘方法

### 复盘模板（每次面试后立即写）

| 复盘项 | 内容 |
| --- | --- |
| 公司/岗位 | XX 公司 - 后端开发 - 社招 |
| 面试轮次 | 一面/二面/HR 面 |
| 面试时长 | XX 分钟 |
| 被问到的问题 | 列出所有问题 |
| 回答好的问题 | 哪些回答流畅、面试官点头 |
| 回答差的问题 | 哪些卡壳、答非所问 |
| 面试官追问点 | 哪个方向反复深挖 |
| 情绪状态 | 紧张/放松/有压力 |
| 改进点 | 下次要准备什么 |
| 总结 | 一句话总结这次面试 |

### 复盘节奏
- **当天**：趁记忆新鲜，花 15 分钟填写复盘表。
- **每周**：汇总本周所有面试，找出重复出现的薄弱点。
- **每月**：调整准备策略，把高频失分点变成下月重点攻克方向。

### 复盘价值
- **识别模式**：发现「每次问到 Redis 集群就卡壳」→ 下周专攻。
- **追踪进步**：同类型题目从「答不上」到「答得一般」到「答得好」。
- **面试是双向选择**：面试官的提问风格也暴露了团队关注点——关注点你不感兴趣可能是信号。

### 15.2 按算法思想分类

| 算法思想 | 高频题 | 核心思路 |
| --- | --- | --- |
| **动态规划** | 爬楼梯、零钱兑换、最长子序列、编辑距离 | 状态定义 + 转移方程 |
| **双指针** | 接雨水、三数之和、盛最多水的容器 | 对撞/快慢指针 |

### 15.3 刷题策略

| 策略 | 方法 |

## 十八、行为面试STAR框架进阶

### 18.1 STAR故事准备清单

| 故事类型 | 准备数量 | 示例场景 |
| --- | --- | --- |
| **成功项目** | 2-3个 | 带领团队交付关键项目、解决技术难题、推动技术升级 |
| **失败经历** | 1-2个 | 项目延期、线上故障、沟通失误——重点讲反思和改进 |
| **冲突处理** | 1-2个 | 需求变更冲突、技术方案分歧、跨部门协作矛盾 |
| **领导力** | 1-2个 | 带新人、做技术分享、推动流程改进 |

### 18.2 STAR回答模板

**成功项目示例**：
- **S（背景）**：公司要上线一个新功能，时间紧（2周），技术方案不确定。
- **T（任务）**：我负责技术方案设计和核心代码开发，需要在1周内完成方案评审。
- **A（行动）**：我调研了3个方案，用POC验证了核心假设，组织技术评审会讨论，最终选定方案B。
- **R（结果）**：功能按时上线，性能提升30%，获得团队认可和季度优秀员工。

**失败经历示例**：
- **S（背景）**：负责一个数据迁移项目，预估2周完成。
- **T（任务）**：我需要在2周内完成1000万条数据的迁移。
- **A（行动）**：低估了数据质量问题，第3天发现数据不一致，紧急调整方案，加班修复。
- **R（结果）**：延期3天完成，但数据完整性100%。反思：下次要做数据质量评估，预留buffer。

### 21.2 行为面试回答模板

**公式：情境 + 任务 + 行动 + 结果 + 反思**

**示例：最有成就感的项目**
- **情境**：公司电商平台登录系统在促销期间频繁超时
- **任务**：优化登录系统性能，将响应时间从500ms降低到100ms以内
- **行动**：
  1. 分析日志发现MySQL慢查询
  2. 引入Redis缓存用户Session
  3. 优化MySQL查询+引入连接池
- **结果**：响应时间降低90%，QPS提升10倍
- **反思**：性能优化要先监控后优化，不能凭感觉

## 二十一、薪资谈判策略

### 21.1 谈判核心原则

| 原则 | 说明 | 具体做法 |
|------|------|---------|
| 了解市场 | 知道市场行情 | 查看Levels.fyi等薪资数据 |
| 有备选方案 | 谈判的最大筹码 | 拿到多个offer再谈 |
| 价值先行 | 先展示价值再谈薪资 | 强调能为公司带来什么 |
| 数据说话 | 用数据支撑要求 | 量化过往业绩与贡献 |

### 21.2 常见谈判场景

| 场景 | 策略 | 预期结果 |
|------|------|---------|
| 首次报价 | 在报价基础上加15-20% | 最终薪资接近预期 |
| 多offer竞争 | 用其他offer压价 | 提升薪资+签字费 |
| 内部晋升 | 量化贡献+市场对标 | 涨薪20-30% |
| 跳槽谈薪 | 综合评估（base+股票+签字费） | 整包提升30%+ |

- **时机把握**：拿到口头offer后再谈薪资，不要过早暴露薪资预期，掌握主动权。
- **总包思维**：不要只看base salary，要谈总包（base+股票+签字费+奖金），有时签字费是最大的差异点。
- **谈判筹码**：有竞争力的谈判筹码包括：多个offer、稀缺技能、行业经验、可量化的业绩。

> 来源：《薪资谈判》、Levels.fyi薪资数据、程序员客栈

## 二十五、薪资谈判详解

### 25.1 薪资谈判准备

| 准备内容 | 具体做法 | 重要性 |
|---------|---------|--------|
| **市场调研** | 了解目标公司薪资范围 | ⭐⭐⭐⭐⭐ |
| **自我评估** | 明确自己的价值和底线 | ⭐⭐⭐⭐⭐ |
| **对比分析** | 手上有几个offer | ⭐⭐⭐⭐ |
| **谈判策略** | 确定谈判目标和底线 | ⭐⭐⭐ |

### 25.2 薪资谈判技巧

- **先让对方报价**：不要先说自己的期望薪资，让HR或面试官先出价。
- **强调综合价值**：不只是谈数字，要强调你能带来的价值。
- **留有余地**：期望薪资可以比目标薪资高10-15%，给谈判留空间。
- **书面确认**：最终薪资要书面确认，避免口头承诺无法兑现。
- **不要急于表态**：拿到offer后，可以考虑1-2天再回复。

### 25.3 不同场景谈判策略

| 场景 | 策略 | 注意事项 |
|------|------|---------|
| **应届生** | 强调潜力+学习能力 | 不要过于强调薪资 |
| **跳槽** | 强调经验+成果 | 可以要求30%以上涨幅 |
| **内部晋升** | 强调贡献+成长 | 提前准备成果清单 |
| **被挖角** | 保持冷静、货比三家 | 不要被高薪冲昏头脑 |
