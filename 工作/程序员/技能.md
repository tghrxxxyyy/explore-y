# 程序员 · 核心技能（含国产技术栈与 AI 应用）

> 从「会写代码」到「能交付系统，并在中国市场有竞争力」。本文给出技能地图与学习建议，分基础、语言、工程、国产栈、AI 应用、软技能六块，附开源学习资源。

## 一、计算机基础（越往后越值钱）

- **数据结构与算法**：数组/链表/树/图/排序/动态规划——面试与性能优化根基。刷题用 LeetCode / 牛客网。
- **计算机网络**：TCP/IP、HTTP/HTTPS、DNS、WebSocket、TLS。国内常考 HTTPS 握手、HTTP/2/3、CDN。
- **操作系统**：进程/线程、内存、IO、并发、锁。理解 Linux 进程模型对服务端至关重要。
- **数据库**：SQL、索引（B+树）、事务（ACID、隔离级别）、范式；NoSQL（Redis/MongoDB）适用场景。**国产库**：达梦 DM、GaussDB、人大金仓、TiDB（见第四节）。
- **设计模式与架构**：SOLID、分层、微服务、事件驱动、CQRS。国内企业最爱 Spring Boot + 微服务。

> 📘 中文神级笔记：[`CyC2018/CS-Notes`](https://github.com/CyC2018/CS-Notes)、[`doocs/advanced-java`](https://github.com/doocs/advanced-java)（doocs 进阶 Java，覆盖高并发/分布式/JVM）。

## 二、编程语言（国内偏好 + 选型建议）

| 语言 | 国内地位 | 主战场 | 备注 |
| --- | --- | --- | --- |
| **Java** | 企业级绝对主力 | 互联网后端、银行/国企核心系统、信创迁移 | 生态庞大，Spring Boot/Cloud 是标配 |
| **Go** | 云原生首选、上升快 | 微服务、中间件、K8s 生态、高并发 | 并发模型（goroutine）友好，字节重度使用 |

| **JavaScript / TypeScript** | 前端+全栈必备 | Web、小程序、Node 后端、鸿蒙 ArkTS | TS 已成大型项目事实标准 |
| **C / C++** | 底层/游戏/高性能 | 引擎、交易系统、嵌入式、信创内核 | 性能与可控性强 |
| **Rust** | 系统级新宠、安全 | 信创安全模块、区块链、高性能组件 | 内存安全，学习曲线陡但前景好 |

## 三、工程能力（决定你能不能「交付」）

- **版本控制**：Git 工作流（分支、PR、rebase、cherry-pick）。参考 [`tiimgreen/github-cheat-sheet`](https://github.com/tiimgreen/github-cheat-sheet)。国内团队多用 GitLab / Gitee / 工蜂。
- **测试**：单元/集成/端到端，TDD 思维；框架 pytest / Jest / JUnit。AI 在「测试与文档」上增值最大。
- **CI/CD**：GitHub Actions、GitLab CI、Jenkins、Gitea Actions；自动化构建与发布。
- **容器化与云原生**：Docker、Kubernetes、Helm；服务网格 Istio。云厂商：阿里云/腾讯云/华为云。
- **调试与性能**：会看日志、会 profiling（perf、Arthas、Py-Spy）、会排查内存泄漏与慢查询。
- **可观测性**：Prometheus + Grafana + Loki + Jaeger（链路追踪）——国内中大型团队标配。

## 四、国产技术栈（信创能力，国内差异化竞争力）

> 信创（信息技术应用创新）是「2+8+N」国家战略：党政 + 金融/电信/能源 + 全行业国产化。掌握国产栈能吃到政策红利，也是银行/政务岗硬要求。

### 4.1 国产操作系统
- **统信 UOS / 麒麟 OS**（桌面/服务器）：类 Linux，熟悉 UKUI/DDE 桌面、包管理、适配。
- **OpenEuler**（云原生服务器 OS，华为开源）：K8s 友好，国内政企云主流。
- **OpenHarmony / HarmonyOS**（物联网/移动）：用 **ArkTS + ArkUI** 开发，一次开发多端部署。

### 4.2 国产数据库
- **达梦 DM（DMSQL）**：金融/政务迁移 Oracle 首选，熟悉 DMETL 迁移工具。
- **GaussDB（PL/pgSQL 系）**：华为分布式库，适配 PostgreSQL 生态。
- **人大金仓 KingBase、南大通用 GBase**：兼容性迁移场景。
- **TiDB**：国产分布式 NewSQL，兼容 MySQL，互联网使用广。

### 4.3 国产芯片与架构
- **鲲鹏（ARM64）**、**飞腾**、**龙芯（LoongArch）**、**RISC-V**：编译与部署需注意架构差异。

### 4.4 国产中间件与框架
- 东方通、宝兰德（国产中间件）；Spring Boot / gRPC / Qt（跨平台）；MindSpore / PaddlePaddle（国产 AI 框架）。

### 4.5 信创迁移典型路径
- C#/.NET 开发者 → 转 **Java（Spring Boot）+ 达梦/高斯**（语法相近）。
- C++ 开发者 → 续用 C/C++，补 **Rust + OpenEuler 内核/驱动**。
- Python 开发者 → 续用 Python，切 **MindSpore + 昇腾 NPU** 做 AI。
- JS 开发者 → 转 **ArkTS/ArkUI** 做鸿蒙应用。

### 4.6 安全合规（国内必懂）
- **等保 2.0**：《信息安全技术 网络安全等级保护基本要求》，系统按重要度分五级定级、测评、备案。
- **国密算法**：SM2（非对称）/ SM3（哈希）/ SM4（对称），金融与政务系统强制或推荐使用。
- **个人信息保护法 / 数据安全法**：涉及用户数据的系统必须满足合规采集、存储、跨境要求。

## 五、AI 应用开发（当下最被争抢的技能）

> 不要只「会调 API」，要做「能把 AI 嵌入业务流、用大模型重构流程」的人。

| 能力 | 学什么 | 价值 |
| --- | --- | --- |
| **Prompt Engineering** | 结构化提示、少样本/思维链、系统提示设计 | 入门快，所有 AI 应用的起点 |
| **RAG（检索增强生成）** | 向量库（Milvus/Chroma/Qdrant）、Embedding、切片、重排 | 企业知识库标配，解决幻觉 |
| **Agent 编排** | 工具调用、规划-执行、多智能体、MCP 协议 | 2026 「Agent 大年」核心岗 |

| **模型服务化** | vLLM / TGI 推理部署、量化、GPU 资源调度 | 把模型跑起来、跑得便宜 |
| **评测** | 准确率/幻觉率/安全护栏、自动评测集 | 保证 AI 产品可控可上线 |

**国内大模型生态**：DeepSeek、通义千问 Qwen、智谱 GLM、文心一言、豆包、Kimi——多为主流 OpenAI 风格 API，迁移成本低。

## 九、软技能清单与实践方法

### 9.1 沟通表达

- **结构化表达**：结论先行、分层论述、数据支撑。使用「总—分—总」框架。
- **向上汇报**：说结论 → 说进展 → 说风险 → 说方案。避免「技术细节堆砌」。
- **跨部门沟通**：理解对方 KPI，用对方语言说话。技术问题翻译成业务影响。
- **书面表达**：邮件简洁有重点，IM 消息一次说完（避免连续发 10 条 3 秒语音）。

### 9.2 团队协作

- **代码协作**：PR 规范、Code Review 礼仪、冲突解决流程。
- **需求协作**：主动确认边界、书面记录分工、及时同步进度。
- **冲突处理**：对事不对人、先私下沟通、升级时只摆事实。
- **知识共享**：技术分享、文档沉淀、新人 mentoring——建立「靠谱」口碑。

### 9.3 文档能力

| 文档类型 | 核心要素 | 常见错误 |
| --- | --- | --- |
| **技术方案** | 背景、目标、方案对比、风险、排期 | 只写结论不写对比过程 |
| **API 文档** | 接口定义、参数说明、示例、错误码 | 缺少示例和错误处理 |
| **复盘报告** | 问题描述、根因分析、改进措施、责任人 | 只描述现象不分析根因 |
| **项目总结** | 目标、过程、成果、经验教训、数据 | 夸大成果、回避问题 |

### 9.4 时间管理

- **四象限法**：重要紧急 → 立即做；重要不紧急 → 计划做；紧急不重要 → 委托做；不重要不紧急 → 少做。
- **番茄工作法**：25 分钟专注 + 5 分钟休息，每 4 个番茄长休 15 分钟。
- **深度工作**：每天留出 2–4 小时不被打扰的整块时间，处理核心任务。
- **周复盘**：每周五花 30 分钟回顾：本周完成了什么、卡在哪里、下周优先级。

## 十、学习方法论（高效成长路径）

### 10.1 费曼学习法

- **步骤**：选择概念 → 用简单语言解释 → 发现卡壳点 → 回去学 → 再次简化解释。
- **实践**：学完一个技术点，写一篇「给新手看的教程」或录一个 5 分钟讲解视频。
- **效果**：能讲清楚说明真懂了；讲不清楚的地方就是你的知识盲区。

### 10.2 刻意练习

- **核心原则**：在学习区边缘反复练习，即时反馈，持续迭代。
- **实践**：
  - 刷 LeetCode 时，做完不看答案先想 10 分钟，再看最优解，分析差距。
  - 读源码时，先猜实现再验证，对比自己的思路。
  - 做项目时，主动挑战超出能力范围 20% 的任务。

### 10.3 输出倒逼输入

- **写作**：每周写一篇技术博客，倒逼自己整理知识体系。
- **分享**：在团队内做技术分享，准备过程就是深度学习过程。
- **开源**：给开源项目提 PR，阅读他人代码是最好的学习。
- **教学**：带新人、做内部培训，在教的过程中发现自己没掌握的部分。

### 10.4 项目驱动学习

- **选项目原则**：解决真实问题 > 轮子项目 > 纯练习项目。
- **学习路径**：遇到问题 → 搜索/问人 → 实践 → 总结 → 输出文档。
- **闭环思维**：代码写完不够，要部署上线、监控运行、收集反馈、持续迭代。

## 十一、技术深度 vs 广度：T 型人才培养

### 11.1 T 型能力模型

```
广度（横向了解多个领域）
├──────────────────────────────────────────
│ 深度（纵向精通一个方向）
│        │
│        │  Java/Go 后端
│        │  系统设计
│        │  性能优化
│        │  分布式系统
│        ▼
```

- **一专**：某个方向扎到能解决别人解决不了的问题（如高并发、性能调优、架构设计）。
- **多能**：前端/后端/运维/产品至少能对话，能参与技术选型和方案评审。
- **AI 杠杆**：会用 AI 工具提效，能把 AI 嵌入业务流。

### 11.2 专精 vs 全栈选择

| 维度 | 专精路线 | 全栈路线 |
| --- | --- | --- |
| **适合阶段** | 3 年以上经验 | 0–3 年或独立开发 |
| **薪资天花板** | 高（稀缺性溢价） | 中高（需产品感加持） |
| **就业难度** | 岗位少但竞争也少 | 岗位多但竞争激烈 |
| **35 岁稳定性** | 高（深度壁垒） | 中（广度可迁移） |
| **独立开发** | 需补充其他技能 | 天然适合 |
| **技术管理** | 适合（深度说服力） | 适合（广度协调力） |

### 11.3 各阶段能力重点

| 阶段 | 深度目标 | 广度目标 |
| --- | --- | --- |
| **0–2 年** | 精通 1 门语言 + 1 个框架 | 了解前后端基础、会部署 |
| **2–5 年** | 深入一个业务域/技术方向 | 能做技术选型、方案评审 |
| **5–8 年** | 架构设计、性能优化、疑难问题 | 跨团队协作、业务理解 |
| **8 年+** | 行业级技术影响力 | 战略级技术规划、团队建设 |

## 十四、学习方法论（高效成长路径）

### 14.1 费曼学习法实践

- **核心步骤**：选择概念→用简单语言解释→发现卡壳点→回去学→再次简化解释。
- **程序员应用**：学完一个技术点，写一篇"给新手看的教程"或录一个5分钟讲解视频。
- **检验标准**：能讲清楚说明真懂了；讲不清楚的地方就是你的知识盲区。
- **进阶实践**：在团队内做技术分享，准备过程就是深度学习过程；收到提问能即时解答说明掌握了。

### 14.2 刻意练习方法

- **刷题策略**：做完不看答案先想10分钟，再看最优解，分析差距；每种题型总结答题模板。
- **源码阅读**：先猜实现再验证，对比自己的思路；从简单模块入手，逐步挑战核心逻辑。
- **项目驱动**：主动挑战超出能力范围20%的任务；遇到问题先搜索/问人，再实践、总结、输出文档。
- **闭环思维**：代码写完不够，要部署上线、监控运行、收集反馈、持续迭代。

### 14.3 输出倒逼输入

| 输出形式 | 频率建议 | 核心价值 |
| --- | --- | --- |
| **技术博客** | 每周1-2篇 | 倒逼整理知识体系、建立个人品牌 |
| **技术分享** | 每月1次 | 准备过程就是深度学习、提升表达能力 |
| **开源贡献** | 持续 | 阅读他人代码是最好的学习、社区人脉 |
| **新人带教** | 有机会就做 | 在教的过程中发现自己没掌握的部分 |

### 14.4 知识管理框架

- **输入**：技术文章/视频/源码/会议→笔记整理→知识卡片。
- **处理**：分类归档→建立关联→定期复盘→形成体系。
- **输出**：博客/分享/开源/项目应用→反馈→迭代优化。
- **工具推荐**：Notion/Obsidian/语雀做知识库；GitHub管理代码和笔记；飞书/钉钉做团队协作。

## 十五、T型人才培养路径

### 15.1 T型能力模型详解

```
广度（横向了解多个领域）
├──────────────────────────────────────────
│ 深度（纵向精通一个方向）
│        │
│        │  Java/Go 后端
│        │  系统设计
│        │  性能优化
│        │  分布式系统
│        ▼
```

- **一专**：某个方向扎到能解决别人解决不了的问题（如高并发、性能调优、架构设计）。
- **多能**：前端/后端/运维/产品至少能对话，能参与技术选型和方案评审。
- **AI 杠杆**：会用AI工具提效，能把AI嵌入业务流，用1人=过去3人。

### 15.2 各阶段能力重点

| 阶段 | 深度目标 | 广度目标 | 学习时间分配 |
| --- | --- | --- | --- |
| **0-2年** | 精通1门语言+1个框架 | 了解前后端基础、会部署 | 80%深度+20%广度 |
| **2-5年** | 深入一个业务域/技术方向 | 能做技术选型、方案评审 | 70%深度+30%广度 |
| **5-8年** | 架构设计、性能优化、疑难问题 | 跨团队协作、业务理解 | 60%深度+40%广度 |
| **8年+** | 行业级技术影响力 | 战略级技术规划、团队建设 | 50%深度+50%广度 |

### 15.3 专精vs全栈选择矩阵

| 维度 | 专精路线 | 全栈路线 |
| --- | --- | --- |
| **适合阶段** | 3年以上经验 | 0-3年或独立开发 |
| **薪资天花板** | 高（稀缺性溢价） | 中高（需产品感加持） |
| **就业难度** | 岗位少但竞争也少 | 岗位多但竞争激烈 |
| **35岁稳定性** | 高（深度壁垒） | 中（广度可迁移） |
| **独立开发** | 需补充其他技能 | 天然适合 |
| **技术管理** | 适合（深度说服力） | 适合（广度协调力） |

## 十七、程序员软技能提升

### 17.1 沟通表达能力

| 场景 | 技巧 | 示例 |
|------|------|------|
| 技术方案评审 | 先说结论，再说方案 | "建议用方案A，因为..." |
| 跨部门沟通 | 用对方听得懂的语言 | 对业务说价值，对技术说实现 |
| 需求讨论 | 追问"为什么"，挖掘真实需求 | "这个功能解决什么问题" |
| 代码评审 | 指出问题+给建议 | "这里有性能问题，建议..." |

- **金字塔原理**：汇报工作先说结论，再说原因和细节，让听者快速抓住重点。
- **换位思考**：与不同角色沟通时切换语言体系，与产品聊用户体验，与运营聊转化率。

### 17.2 时间管理方法

| 方法 | 说明 | 适用场景 |
|------|------|---------|
| 番茄工作法 | 25分钟专注+5分钟休息 | 日常编码 |
| 深度工作 | 长时间无干扰专注 | 复杂技术问题 |
| GTD | 任务收集-整理-执行-回顾 | 项目管理 |
| 四象限法 | 按紧急重要程度排序 | 任务优先级 |

- **深度工作**：每天安排2-4小时深度工作时间，关闭IM通知，专注于最重要的任务。
- **批量处理**：将相似任务集中处理，如统一回复邮件、统一处理bug，减少上下文切换。

### 17.3 技术影响力

| 方式 | 说明 | 投入 |
|------|------|------|
| 技术博客 | 持续输出技术文章 | 中 |
| 开源项目 | 贡献或维护开源项目 | 高 |
| 技术演讲 | 在meetup或会议上分享 | 中 |
| 出版书籍 | 写技术书籍 | 高 |
| 内部分享 | 在公司内做技术分享 | 低 |

- **持续输出**：技术影响力需要持续积累，每周写一篇技术文章，一年就是50篇，量变引起质变。
- **选题策略**：写解决真实问题的文章，而不是"XX入门教程"，解决痛点的文章更容易获得传播。

### 17.4 职场情商

| 场景 | 低情商做法 | 高情商做法 |
|------|----------|----------|
| 需求不合理 | "这做不了" | "这个需求可以做，但成本较高，建议..." |
| 被批评 | 解释/反驳 | 先接受，再讨论改进方案 |
| 同事求助 | "我很忙" | "我手上有个急事，忙完帮你看看" |
| 功劳被抢 | 沉默/抱怨 | 适当展示自己的贡献 |

- **向上管理**：主动汇报工作进展，让老板知道你在做什么，不要等老板来问。
- **功劳分享**：项目成功时主动提及团队成员的贡献，建立良好的协作关系。

## 十三、学习方法论

### 13.1 费曼学习法

| 步骤 | 内容 | 效果 |
| --- | --- | --- |
| **选择概念** | 选择要学习的概念 | 明确目标 |
| **教给别人** | 用简单语言解释 | 发现理解盲区 |
| **简化** | 用更简单的语言重新解释 | 深化理解 |
| **回顾** | 回顾并重新学习 | 补充知识漏洞 |

### 13.2 主题学习法

| 步骤 | 内容 | 时间 |
| --- | --- | --- |
| **确定主题** | 选择一个技术主题 | 1天 |
| **收集资料** | 找3-5个优质资源 | 1-2天 |
| **系统学习** | 按顺序学习 | 1-2周 |
| **输出总结** | 写文章或做分享 | 1-2天 |
| **实践验证** | 做一个小项目 | 1-2周 |

### 13.3 刻意练习法

| 要素 | 说明 | 示例 |
| --- | --- | --- |
| **明确目标** | 设定具体、可衡量的目标 | 每天刷1道算法题 |
| **专注投入** | 全神贯注，不分心 | 番茄工作法 |
| **即时反馈** | 及时了解对错 | LeetCode判题 |
| **走出舒适区** | 挑战略高于当前能力的任务 | 从Easy到Medium |

> 来源：学习方法论参考《学习之道》（芭芭拉·奥克利）、《刻意练习》（安德斯·艾利克森）

## 十六、程序员健康指南

### 16.1 职业病预防

| 疾病 | 预防措施 |
|---|---|
| **颈椎病** | 保持正确坐姿、定时活动 |
| **腰椎间盘突出** | 使用腰靠、避免久坐 |
| **鼠标手** | 使用人体工学鼠标、定期休息 |
| **干眼症** | 20-20-20法则（每20分钟看20英尺外20秒） |
| **失眠** | 规律作息、避免睡前看屏幕 |

### 16.2 健康生活习惯

| 习惯 | 说明 |
|---|---|
| **规律运动** | 每周至少3次运动 |
| **健康饮食** | 均衡饮食、少吃外卖 |
| **充足睡眠** | 每天7-8小时睡眠 |
| **定期体检** | 每年至少一次体检 |
| **心理调节** | 学会释放压力 |
