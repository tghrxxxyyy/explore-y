> 按「副业用途」分组，每个项目含 **2026-07 实时星标**、简介、语言/许可证、对副业的价值与用法。数据于 **2026-07-27** 通过 GitHub API 抓取，星标会持续变化，以仓库当前数据为准。

## 一、AI 应用 / 智能体（2026 最热副业赛道）

> 用 RAG / Agent 做企业知识库、垂直助手，私有化部署收年费/项目费。这是当下程序员副业里「单价最高、需求最旺」的方向。

### [`langgenius/dify`](https://github.com/langgenius/dify) ⭐ 150.4k
- **简介**：可视化构建 Agent 工作流与 RAG 管道，支持丰富模型与工具，可云/VPC/私有化部署，从原型到生产一体化。
- **语言 / 许可证**：TypeScript / **自定义许可（NOASSERTION，商用有约束，托管式服务需注意条款）**。
- **官网**：https://dify.ai
- **副业价值**：帮企业「零代码」搭知识库/客服/内部助手，按项目或月费收费；也可做 Dify 部署培训。
- **用法**：本地 `docker compose` 起一套，给客户演示「公司制度问答机器人」，谈私有化部署单。

### [`labring/FastGPT`](https://github.com/labring/FastGPT) ⭐ 29.1k
- **简介**：基于 LLM 的知识库平台，开箱即用的数据处理、RAG 检索、可视化 AI 工作流编排（国内团队，对中文/国产模型 Qwen/DeepSeek 支持好）。
- **语言 / 许可证**：TypeScript / **自定义许可（商用需看其商业授权）**。
- **官网**：https://fastgpt.io
- **副业价值**：比 Dify 更偏「知识库问答」细分，私有化部署到客户内网做「企业大脑」很顺手。
- **用法**：部署后接客户内部文档，做检索增强客服/培训助手，收部署+维护费。

### [`OpenBMB/ChatDev`](https://github.com/OpenBMB/ChatDev) ⭐ 33.8k
- **简介**：清华 OpenBMB 出品，用「多智能体协作」自动完成软件开发（产品经理/程序员/测试等角色），ChatDev 2.0「Dev All through LLM」。
- **语言 / 许可证**：Python / **Apache-2.0（可商用）**。
- **副业价值**：研究/演示用；可做「AI 编程工坊」内容，或基于思路做垂直场景自动化。
- **用法**：跑通一个 demo，写成技术文章/视频，沉淀为 AI 方向影响力。

### [`vllm-project/vllm`](https://github.com/vllm-project/vllm) ⭐ 87.3k
- **简介**：高吞吐、省显存的大模型推理与服务引擎（支持 Qwen/DeepSeek/Kimi 等国产模型）。
- **语言 / 许可证**：Python / **Apache-2.0（可商用）**。
- **副业价值**：做「模型私有化部署」服务的技术底座——客户要本地跑大模型，你帮调通 vLLM + 量化。
- **用法**：学量化与显存优化，给有数据合规要求的企业做本地模型部署顾问。

## 六、避坑（许可证红线）

- **AGPL-3.0**（`immich`）：修改后提供网络服务须开源衍生代码。
- **GPL-3.0**（`1Panel`/`dataease`）：若分发修改后的版本须开源；单纯自托管对内使用通常 OK，但对外提供修改版服务要谨慎。
- **自定义许可**（`dify`/`FastGPT`/`PostHog`）：商用前务必读其 LICENSE，部分禁止托管式竞品或需商业授权。
- **fair-code**（`n8n`）：商用需看其许可条款。
- **MIT/Apache-2.0**（`cal.diy`/`vllm`/`ChatDev`）：可闭源商用，最省心。

## 八、如何参与开源（从 0 到 1）

### 参与路径
1. **用开源项目**：选一个你日常使用的项目，深入阅读文档和源码。
2. **提 Issue**：发现 bug 或提 feature request，写清楚复现步骤和环境。
3. **修 Bug**：从标记 `good first issue` 的 issue 入手，提交第一个 PR。
4. **写文档**：修复错别字、补充示例、翻译文档——文档贡献是最容易被接受的。
5. **贡献代码**：理解项目架构后，开始实现功能或优化性能。

### 参与收益
- **简历加分**：开源贡献经历是技术能力的硬证明。
- **人脉积累**：与项目维护者和其他贡献者建立联系。
- **技术提升**：阅读优秀项目源码是最好的学习方式。
- **影响力**：持续贡献者可能成为 Committer/Maintainer。

### 注意事项
- 遵循项目的 Contributing Guidelines。
- PR 描述清晰（改了什么、为什么改、测试方法）。
- 不要一次性提交大量改动，小步提交更易被接受。
- 尊重项目维护者的决策，即使被拒绝也不要气馁。

## 九、开源项目变现方式

### 直接变现
| 方式 | 说明 | 适合项目类型 | 收入预期 |
| --- | --- | --- | --- |
| 付费支持/咨询 | 为企业用户提供技术支持、部署、定制 | 企业级开源工具 | 按小时/项目收费 |
| 托管服务（SaaS） | 提供开源自托管版本的托管服务 | 需要运维的工具 | 月费模式 |
| 商业授权 | 核心功能开源，高级功能闭源（Open Core） | 功能型工具 | 订阅制 |
| 培训/课程 | 围绕开源项目做付费培训 | 学习型/工具型 | 课程/社群收入 |
| 定制开发 | 基于开源项目为客户做定制化开发 | 通用框架/平台 | 项目制收费 |

### 间接变现
- **品牌效应**：开源贡献建立技术品牌，带来更多工作机会和合作邀约。
- **流量入口**：开源项目为个人博客/公众号/知识星球引流。
- **招聘筹码**：开源贡献经历在求职时是强加分项。
- **行业影响力**：成为某个开源项目的 Committer，在行业内获得话语权。

### 变现案例参考
- **n8n**：开源工作流引擎 → 提供企业版（Fair-code 许可）+ 托管服务（n8n Cloud）。
- **Dify**：开源 AI 平台 → 提供企业版 + 私有化部署服务 + 培训。
- **1Panel**：开源运维面板 → 企业版功能 + 托管服务 + 培训认证。

> 来源：开源参与与变现参考 GitHub 官方文档、开源社、OSCHINA 社区、独立开发者变现案例（Indie Hackers/awesome-indie-cn）

## 十、开源许可证选择指南

### 常见许可证对比

| 许可证 | 商业使用 | 修改分发 | 闭源 | 专利授权 | 适合场景 |
|--------|---------|---------|------|---------|---------|
| MIT | ✓ | ✓ | ✓ | ✗ | 最宽松，适合个人项目 |
| Apache-2.0 | ✓ | ✓ | ✓ | ✓ | 企业级项目，有专利保护 |
| GPL-3.0 | ✓ | ✓（需开源） | ✗ | ✓ | 希望衍生作品也开源 |
| AGPL-3.0 | ✓ | ✓（需开源） | ✗ | ✓ | SaaS服务，防止闭源 |
| BSD-2-Clause | ✓ | ✓ | ✓ | ✗ | 类似MIT，稍严格 |
| MPL-2.0 | ✓ | ✓（文件级） | ✓ | ✓ | 文件级开源，可闭源其他文件 |

### 副业项目许可证选择建议

| 项目类型 | 推荐许可证 | 原因 |
|---------|-----------|------|
| 个人工具/库 | MIT | 最宽松，容易被采用 |
| 企业级工具 | Apache-2.0 | 有专利保护，企业更放心 |
| 想保持开源 | GPL-3.0 | 衍生作品也必须开源 |
| SaaS服务 | AGPL-3.0 | 防止他人闭源你的代码 |
| 不确定 | MIT | 先用MIT，后续可改 |

### 许可证选择决策树

1. **想完全自由** → MIT
2. **想保护专利** → Apache-2.0
3. **想强制开源** → GPL-3.0
4. **做SaaS服务** → AGPL-3.0
5. **想商业化** → MIT/Apache-2.0（可闭源商用）

> 来源：choosealicense.com、GitHub官方文档

## 十一、GitHub Sponsors与开源变现

### GitHub Sponsors机制

- **是什么**：GitHub官方的开源开发者赞助平台。
- **收入来源**：个人或企业每月赞助你的开源工作。
- **分成比例**：GitHub不抽成（0%手续费），全额到手。
- **门槛**：需要申请，审核通过后才能开通。
- **税务**：赞助收入需要报税（按当地税法）。

### 提高赞助收入的方法

- **持续贡献**：定期更新项目，保持活跃度。
- **高质量文档**：好的文档让更多人受益，增加赞助意愿。
- **社区互动**：及时回复issue和PR，建立良好口碑。
- **赞助层级**：设置不同赞助等级（如$5/$10/$50），提供不同权益。
- **感谢公开**：在README中公开感谢赞助者。

### 其他开源变现渠道

| 渠道 | 方式 | 收入预期 |
|------|------|---------|
| GitHub Sponsors | 月度赞助 | $100-$1000+/月 |

| Patreon | 会员订阅 | $200-$2000+/月 |
| 付费支持/咨询 | 企业技术支持 | $100-$500/小时 |
| 托管服务 | SaaS托管版本 | 月费模式 |
| 培训课程 | 围绕项目的培训 | $1000-$10000+/期 |

### 成功案例

- **Evan You（Vue.js）**：通过GitHub Sponsors和Patreon获得稳定赞助。
- **Sindre Sorhus**：大量开源包作者，通过GitHub Sponsors获得收入。
- **PHPMailer**：开源邮件库，通过赞助和咨询服务变现。
